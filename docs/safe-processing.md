# Copernicus SAFE 本地显示与处理

2026-10-01：桌面工程已接入原始 SAFE ZIP → 真彩色 TCI / SCL GeoTIFF → 工作空间显示、像元取值、工程裁剪与同网格拼接。账号授权入口仍位于设置页；没有账号不会被记录为已授权，也不会创建伪下载结果。

## 使用流程

1. 在 Copernicus 目录选择影像，保存工程并下载完整原始产品。下载需要软件内的有效账号授权。
2. 工程内选择“准备真彩色影像”或“准备 SCL”。分别读取原包内的 TCI 10 米、SCL 20 米 JP2，以原始像元值和网格生成本地 GeoTIFF。原包保留。
3. 完成后使用文件卡片的图层图标在工作空间打开，查看源坐标系中的原始 RGB / SCL 像元，或者按工程区域裁剪。多景处理沿用同 CRS、同分辨率、像元对齐与最新有效像元覆盖的规则。

“已准备影像”是从原包转换的来源文件；裁剪与拼接结果另行显示。重复准备复用同一原包校验和、同一类型的运行中或已完成任务。失败和中断的任务可从头重试。工程关联通过父任务及 SHA-256 来源固定，转换文件不会被误标为新下载或裁剪结果。

## 核对内容

- 校验原包的本地路径、实际字节数和固定的 SHA-256；读取时持有文件，Windows 下拒绝写入和替换共享。
- 复用 SAFE 完整中央目录检查：限定所选产品根目录，拒绝目录越界、重复条目、加密和符号链接。
- 从 `MTD_MSIL2A.xml` 核对产品名称、Level-2A 和选定的唯一影像引用；从同一 granule 的 `MTD_TL.xml` 获取 MGRS、UTM CRS、Size 和 Geoposition。拒绝 XML DTD / 外部实体，不用目录包围框代替文件空间信息。
- 核对 JP2 图像头与编码流的尺寸、通道、UInt8 位深、无子采样网格和完整结束标记；严格解码 TCI / SCL，不使用会缩放数值的组件转换函数。SCL 必须为 0–11。
- 流式解压所选 JP2，验证 ZIP CRC；按 256 行区域解码，写出压缩 GeoTIFF，并重新解码全部输出条带，核对像元摘要、尺寸、CRS 和网格后提交。
- 同时保存来源、选定 JP2 / XML 条目、输出网格与 SHA-256 sidecar。取消、失败或崩溃恢复会清理该任务的临时文件和未提交结果。

应用使用锁定的 `jpeg2k 0.10.1` / `openjp2 0.6.1` Rust 解码依赖、`roxmltree 0.21.1` 和带 Deflate 支持的 ZIP 库；不要求用户安装 Python、GDAL 或另一个产品。Rasterio / GDAL 仅用于独立测试。

## 本轮证据与限制

[机器记录](../prototype/qa/safe-processing-verification.json)明确标记本轮使用合成测试文件。可复现来源和哈希保存在 [SOURCE.json](../crates/geod-runtime/fixtures/safe/SOURCE.json)。该文件由独立 GDAL JP2OpenJPEG 可逆编码器生成，使用真实 JP2 编码与 SAFE XML / ZIP 结构，**不是下载的卫星产品**。

- 真彩色 64 × 520 × 3、SCL 32 × 260 的全部 108,160 个样本与独立 JP2 解码值一致，跨条带写出正常；两份工程裁剪的全部 26,100 个样本与原始对应窗口一致。
- 原生运行时接口完成准备、检查、取值、缩略图、裁剪、重复提交复用与新进程恢复。合成文件的哈希和任务来源未变化。
- 明暗主题 1440 宽及 1024 宽共三例浏览器联调使用实际原生处理响应，核对四张本地缩略图、按钮可用状态、两种地图图层及独立像元值，没有页面错误或横向溢出。未控制用户桌面；这不代替真实账号或完整原生窗口交互验收。
- 八项 Rust SAFE 测试覆盖数值一致性、来源变化、取消、错误产品 / CRS / tile、外部实体、错误 JP2 位深 / 尺寸 / 截断、非法 SCL 类别、ZIP CRC、中断重试、重启、缓存和工程处理。

当前适配标准紧凑单 tile Sentinel-2 L2A 的 TCI RGB UInt8 和 SCL Gray UInt8；不支持任意 SAFE 多 granule、JP2 调色板 / alpha / 可变位深、其他传感器或 Sentinel-2 原始反射率波段。下载 ZIP 上限 4 GiB，所选 JP2 入口上限 512 MiB，XML 入口上限 4 MiB；整个 ZIP 的未压缩声明上限 16 GiB。图像尺寸上限 10980，最终 SCL / RGB 查看遵循现有检查器大小限制。解码逐区域运行，取消在区域间生效；完整生产场景的耗时和内存仍待实测。

**尚无真实 Copernicus 账号的成功原包下载或完整生产 SAFE 的正向验证。** NASA HLS 的账号下载同样待验收；已完成软件内授权入口与本地读取 / 处理代码，不能据此宣布五个平台全流程验收通过。

格式参考：[Copernicus 产品格式与元数据](https://sentiwiki.copernicus.eu/web/s2-products)、[JPEG2000 区域解码接口](https://docs.rs/jpeg2k/0.10.1/jpeg2k/struct.DecodeParameters.html)。
