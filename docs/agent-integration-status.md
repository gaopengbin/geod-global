## 当前工程状态查询

“这个工程下载完成了吗”应当直接读取附加的当前工程和真实任务，不需要用户批准另一次只读查询。没有下载任务不能回答为下载成功；任务成功还需要 `succeeded` 且 `settled=true`。当前工程名称、文件状态等不得照抄旧回复。普通状态问题只返回需要的结果，避免重复输出目录、坐标、内部编号和策略说明。

这项改动保留原生写入审核边界。不同模型的自然语言测试与恢复记录分别登记，失败的模型请求保留为失败，不合并进通过数量。

[自然语言查询验收](../prototype/qa/agent-natural-status-verification.json)覆盖三条已有模型路线、8 轮对话和 26 次原生读取。问题没有工具名或工程编号，每轮从当前附加工程读取新名称并查询任务，重启后继续原会话。此组真实状态是任务总数为零；它不代替进行中、失败、已完成任务的逐项验收，也没有发起新的下载。检查正常列表分页与不同类型成果时仍须遵守各自原生契约。

工程任务列表现已支持原生工程筛选，先按完整来源和处理链确认归属，再分页；不会把其他工程任务算进当前工程。已完成任务新增实际文件验收：DeepSeek / Qwen 的 3 轮自然语言对话完成 9 次原生读取，并在重启后继续同一线程；当前工程的一份真实 SCL 文件在对话前后均通过原生校验。8 条其他工程的失败记录是受控干扰数据，不宣称为真实下载失败。7 项新增原生测试覆盖筛选、分页、来源一致性及状态刷新，详见[原工程任务记录](../prototype/qa/agent-project-task-status-verification.json)。运行中和失败状态已由本轮两次实际查询及记录复核补齐：采用明确标注的源连接故障，不是注入任务状态或自然数据源故障，见[运行中及失败记录](../prototype/qa/agent-active-failed-task-verification.json)。

Agent 方案卡片现按最新原生任务显示执行中、输出收尾、失败或完成状态，并显示对应文件名。未知文件大小使用不显示百分比的进度动效；只有 `succeeded` 且 `settled=true` 时提供成果入口，失败和收尾阶段不会提前显示完成。任务大小也按原生数值契约校验。定向组件检查与一个隐藏浏览器页面检查已通过，页面采用明确标注的受控任务快照，没有发起模型调用、下载或自动确认；这项界面验证与本轮实际状态查询的证据分别保留，不互相替代。
