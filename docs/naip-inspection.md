# NAIP 航空影像读取与实际验收

2026-10-04。探索页的 **NAIP · Planetary Computer** 按区域与 UTC 日期检索美国已发布航空影像，提供在线 RGB 地图和四通道原文件工程下载。它不提供卫星云量筛选，也不标为全球覆盖。

## 产品与访问

读取 [Planetary Computer 的 NAIP 集合](https://planetarycomputer.microsoft.com/api/stac/v1/collections/naip)中 `image` 资产，保留红、绿、蓝、近红外四个通道。应用下载完整的该分发 COG；它不是另外一条 USDA 原始采集包或 AWS raw-source 交付链。AWS 的 NAIP 分发包含不同格式和 Requester Pays 条件，不能用本入口的匿名访问能力概括所有 NAIP 路径。[AWS 数据说明](https://registry.opendata.aws/naip/index.html)

无需用户账号。在线地图与原生下载分别获取短期只读容器 SAS，合并并发申请并检查有效期。官方条目、州、年份、网格、象限、UTM 区号、分辨率、日期和四通道顺序须匹配已审核的无签名路径。签名只在内存使用；工程、任务、导出及验收记录保留稳定无签名地址。桌面 CSP 只为 COG 读取增加指定 NAIP Azure 主机。

官方集合当前 `license` 字段为 `proprietary`，同时提供题为 Public Domain 的 USDA 政策链接。保留原字段及链接，来源署名区分 USDA NAIP、Esri 处理和 Microsoft 分发，不自行改写为通用软件许可。

## 本地语义

当前审核分支读取 NAD83 UTM 北区、PixelIsArea、交错 UInt8 × 4、RGB 光度解释、无 NoData 标签。通常第四额外采样为未指定；已审核的历史 `1` 分辨率标记原文件另接受 ExtraSamples=2，但须与官方条目的 RGB / NIR 角色和完整身份绑定，不将它解释为透明通道。其他产品的 alpha 标签不自动接受。UTM 区号和像元间距须匹配资产身份；不把 EPSG:26910 当成 WGS84 的 EPSG:32610。

RGB 显示采用原始前三通道，PNG 的显示透明度独立生成。第四通道是原始 NIR 数值，不用作 alpha；黑色 RGB、NIR=0 都有效。像元查询在重新校验完整 SHA-256 后读取原分辨率四通道。没有反射率校准、云掩膜或科学分析换算。

锁定的 TIFF 库会在 RGB 读取中省略未指定的额外通道。NAIP 分支从同一受管、校验过的文件读取有界数据块，支持无压缩 / Deflate、预测器 1 / 2，精确还原四通道及边缘瓦片；不修改源标签或文件。其他编码与多光谱产品不自动归入该分支。

缩略图复用既有[持久化缓存](thumbnail-cache.md)，最长边 160 像素，按任务、源哈希、资产类型、尺寸与预览版本区分。缓存命中验证文件身份及 PNG，不代替像元检查的完整源校验。NAIP 原文件下载、处理源校验和缓存身份检查共用 4 GiB 单文件上限；原文件网格边长上限为 40,000 像素，处理区域的像元上限仍单独限制，不因此支持任意整景拼接。恢复工程时，目录网格未返回前显示元数据加载状态，防止过早提交地图加载；查询返回后恢复真实影像。

## 四通道工程裁剪与拼接

工程在全部原文件就绪后提供裁剪或拼接按钮，任务复用原有取消、重试及结果管理。只处理同一坐标系、间距与对齐的网格，不重投影或重采样。输出保留四个 UInt8 通道、NAD83 UTM、PixelIsArea 和原始数值，重叠处按工程固定的日期 / 场景排序，后面的有效源覆盖前面。

未覆盖区域和工程多边形孔洞使用独立的 TIFF 内部 1-bit 覆盖掩膜：另一个目录标记 `NewSubfileType=4`、TransparencyMask，压缩保存，与四个影像通道分开。采用 [GDAL GeoTIFF 内部掩膜规范](https://gdal.org/en/stable/drivers/raster/gtiff.html)。主影像不声明数值 NoData，第四通道保持未指定的 NIR。RGB=0 或 NIR=0 的覆盖像元仍有效；预览和缩略图从掩膜生成 alpha。像元查询同时返回四个原值和覆盖状态。

像元与掩膜按有界分块写入临时文件，重新解码、比较哈希和覆盖数量后提交；取消或验证失败不发布结果。掩膜压缩数据也以临时文件暂存，不为整幅影像分配覆盖数组。主 TIFF 及来源 JSON 沿用工程文件导出入口。

[处理验收记录](../prototype/qa/naip-processing-verification.json)使用实际相邻 NE / NW 两景，加州 2022-05-18、0.6 米，共下载 841,078,033 字节。输出 1329 × 934 × 4，大小 1,934,539 字节，SHA-256 为 `eacd40aab5707942f7078dc33a6e1b1285c56ba4785e4133de646e43680d28ac`。

Rasterio/GDAL 识别四个影像通道与独立 dataset mask。NumPy 独立重建源网格和重叠顺序；PROJ/pyproj 将每个像元中心反投影到原始 WGS84 多边形，由 Shapely 判断斜边与孔洞。全部 4,965,144 个通道值与 1,241,286 个覆盖标记一致。不能只将 WGS84 顶点投影后连成 UTM 直线作为同一个区域；那会改变边界像元。

RGB / alpha 预览 768 × 539 与原始输出逐像素一致，缩略图 160 × 112 的透明度一致。原生 API 的有效及无覆盖像元查询均匹配。重启后工程、结果与缩略图恢复，缓存条目字节、PNG 哈希、文件身份和创建时间不变。工程按钮实际提交该处理任务；明暗主题 1440 × 940、紧凑 1024 × 940 的工程 / 工作空间无头交互检查通过，无水平溢出或页面异常。

另用实际 NW 原文件执行单景矩形裁剪：1481 × 1859 × 4、8,988,032 字节，11,012,716 个通道值与原文件窗口全部一致；内部掩膜全部覆盖，没有数值 NoData 标签。SHA-256 为 `2719a7bb9138120160560af15f56af5300f9b51d80230eae84fa15989e2c4807`。Classic TIFF 与 BigTIFF 的四通道 / 掩膜编解码另经夹具测试，包括跨 511 / 512 行分块、非整字节行宽、有效黑色、零 NIR、重叠及空隙。

## 分辨率与历史文件变体

0.3 / 0.6 / 1 米采用对应真实路径约束。历史文件名的 `1` 表示 1 米，目录仍使用 `100cm`；部分文件含两个日期，部分官方 Item ID 的日期比文件名多一个。应用保存完整官方 ID，只在原生官方条目核对确认相同无签名资产后接受这种受限对应关系，不用文件名反向猜造新 ID。

本轮已完整下载佛罗里达相邻两景 1 米和缅因州一景 0.3 米原文件，共 1,912,565,951 字节。三份原件和五份工程结果通过完整哈希、原始四通道、RGB / alpha 预览、23,818,032 个结果通道值与覆盖标记的独立核对；全矩阵离线重启、八张缩略图复用、两种 MCP 会话和五个实际界面处理按钮通过。具体文件、宽高与剩余边界见[分辨率变体验收](naip-resolution-variants.md)。
