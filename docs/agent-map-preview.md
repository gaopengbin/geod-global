# Agent task map preview

Built-in imagery download and project review cards provide **Map preview** before confirmation. A private desktop command checks the selected conversation, its recorded plan reference and the exact plan hash, then reads the pinned area and original asset identities. It neither approves a plan nor creates jobs, projects or files.

Map preview opens a resizable right panel in the existing application shell. The conversation, task card, confirmation button and editable composer stay on the left. It reuses the existing OpenLayers ExploreMap, fetches the exact selected catalog item IDs, verifies their original asset paths against the review, and shows the search area and scene footprints. Every scene defaults checked and all supported COG/provider preview layers load together. Each checkbox changes independent map visibility; show-all/hide-all controls are available. These display controls never change the download review. Public access is prepared for all optical preview sources before rendering. Zoom, fit-all and fit-search-area controls are available. Closing the panel restores the prior layout and focus without resetting the conversation or draft. Switching conversations, replacing the review or navigating to another page dismisses the preview.

Metadata failures retain the original task selection and search area, provide a retry action, and never substitute unrelated imagery. Closing aborts pending metadata requests and disposes the map. Sources without supported online rendering show their footprints with an explicit message. Custom STAC, WCS and processing review cards do not yet use this panel; their existing result/workspace paths remain separate.

Validation includes native pinned-plan and conversation checks, metadata identity and partial-failure tests, panel switching/retry/abort tests, and full-App browser inspection at 1280px light and 900px dark. Browser checks include keyboard resizing, editable drafts and usable confirmation controls beside the map, close/reopen and no modal overlay. They used the selected New York review and real Earth Search item metadata plus successful COG range reads, with controlled desktop IPC. They do not establish native WebView visual acceptance, original-file acquisition or scientific quality. The desktop development executable was rebuilt and started; no installer or release was produced.
