# 公开 STAC POST 搜索与分页

2026-10-03。自定义 STAC 来源现在可以使用声明的 GET 或 POST Item Search。操作入口仍为“设置 → 自定义栅格来源”：连接公开目录、选择集合和区域、查询、选中原始资产、保存到工程，再启动下载。界面不要求用户选择协议方法。

## 请求与来源保存

新连接优先使用有效的公开 POST 搜索链接；仅有 GET 时使用 GET。已有来源保留保存的方法，没有 `searchMethod` 的旧记录默认为 GET，读取时不改写注册文件。每页的 URL、GET / POST 方法及 JSON 请求体与原响应一起持久保存，快照引用包含它们的内容哈希。

下一页按服务声明的方法读取，支持 GET / POST 切换。POST `merge: true` 将分页字段合并到首次查询的请求体，避免带入上一页的临时字段；未声明或为 false 时使用链接自己的请求体。没有声明方法的链接默认为 GET。此行为依据 [STAC API Item Search 1.0](https://github.com/radiantearth/stac-api-spec/blob/v1.0.0/item-search/README.md) 与 [OGC STAC API 标准](https://docs.ogc.org/cs/25-005/25-005.html)。

本地游标绑定来源、集合和初始筛选。循环检测使用完整 URL / 方法 / 请求体，同一 URL 上不同的分页请求不会被误判为重复。重复下一页、歧义链接、越界地址、无效方法或请求体会返回明确错误。请求描述符上限为 16 KiB，快照记录上限为 64 KiB；原有条目数、响应体和请求超时限制继续适用。

传输前优先重新读取条目声明的同源 GET `self` 文档；没有可用 `self` 时按保存的完整页面请求复验，保留 POST 请求体。“原始条目元数据 → 原始分页请求”显示这份记录。已有原文件复用依然检查实际文件路径、大小和完整 SHA-256。

重新搜索可能生成新的目录快照。同一来源、资产、条目、原属性、几何、范围和集合声明一致时，工程保持已有引用。界面读取新旧本地快照核对后，以工程引用下载，继续保留当前搜索的勾选状态；同名但元数据改变的文件不会仅凭条目 ID 合并。

本轮公开服务实际声明 GET / POST，选择 POST；它返回的是 `merge: false` 完整替换请求体。POST-only、`merge: true`、GET / POST 切换、无 `self` 的传输复验与异常协议由明确的控制测试覆盖，不能把它们称为另一真实供应商的端到端验收。

## 当前边界

仍限公开 HTTPS、同源元数据链接和无需自定义请求头的搜索 / 分页；认证、内网、跨主机元数据、临时签名 URL / S3 URI、静态 Catalog 递归、MCP 自定义源工具及通用科学处理待接入。公开分页 `token` 可以作为不透明 JSON 页码保存；链接的请求体 / 请求头中出现密码、授权头或已知访问令牌字段时，拒绝保存这份元数据，不转发其他供应商账号的凭据。

原文件下载、元数据声明、通用第一波段灰度显示与科学校准分别验收；本轮不启用 SCL 分类色板或传感器科学处理，不声称通过 COG 规范认证。无头界面验收不是已安装 Windows WebView 的人工验收。NASA / Copernicus 的软件内入口独立见 [账号授权](provider-accounts.md)，没有账号时不将受保护原文件标为已验收。完整接入目标仍按 [数据域状态表](provider-integration-status.md) 继续推进。
