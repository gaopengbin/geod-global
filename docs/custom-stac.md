# 自定义 STAC 与 GeoTIFF / COG

自定义栅格源沿用现有工程、任务队列和受管原文件目录。用户提交原生保存的目录快照引用；下载地址、原始资产键及来源信息由本地运行时重新解析，不接受界面自行拼出的原文件地址。

## 连接与选择

在探索页或“设置 → 自定义栅格来源”打开管理入口，选择来源类型、填写名称和公开地址。连接后选择原始资产，保存到新工程或已有工程，再启动下载。工程名称与区域仍使用现有工程规则。

- STAC API：连接公开 HTTPS 入口，读取声明的集合与 GET / POST Item Search 能力，按当前区域及可选时间检索。新连接优先使用声明的 POST 搜索，旧连接保持保存的方法。分页结果明确区分还有下一页、查询结束和达到本地上限；无需用户选择请求方法。
- STAC Item：保存单个公开 Item 文档，选择其中实际列出的 TIFF 资产。原始资产名、媒体类型和声明保留；不能用 `red`、`scl`、`elevation` 等名字自动推断科学处理方法。
- GeoTIFF / COG URL：独立保存原文件 URL 与少量头部探测结果；不伪造 STAC Item、采集时间或许可声明。读取 TIFF 不等于通过 COG 规范验证。

元数据与原文件可位于不同公开主机；当前目录发现、集合和分页链接须留在所连接的同一来源主机。这也会拒绝部分有效但跨主机链接集合的独立 Item，界面会给出连接错误，不能将其标为连接成功。每个请求遵循软件代理设置，验证公开地址，禁用自动重定向，不向自定义源转发 NASA / Copernicus 等账号的凭据。临时签名地址、S3 URI、静态 Catalog 递归遍历、要求自定义请求头的搜索或分页暂不属于这一实现。GET / POST 分页与验收边界见 [POST 搜索](stac-post-search.md)。

本增量提供桌面命令、本地 HTTP 与 `stac` CLI 操作。现有 MCP 工具尚未增加自定义源发现、搜索和资产选择接口，不能将这一增量描述为 MCP 接入完成。

## 工程与任务

自定义选项单独保存在工程的 `stacItems` 中，旧 `scenes` 记录保持原义。自定义资产、WCS 请求与既有场景合计最多 32 个选项；追加文件保留工程已有区域。保存工程与启动下载为两个明确步骤。任务使用原生快照和资产键标识，复用已有排队、取消、失败重试、重启中断恢复、临时文件提交及 SHA-256 校验。

目录重新读取改变获取时间、查询参数或分页记录，但选定资产及条目、属性、几何和集合声明一致时，保留工程已有引用，避免生成重复文件。界面核对新旧本地快照后使用工程的原引用下载，当前勾选状态保持不变。复用已完成文件前再次校验受管路径、大小和完整 SHA-256；文件缺失或内容被修改时重新排队，并保留旧任务的失败原因。已经存在同一引用的排队、执行中或完成任务时，重试旧失败任务不会再创建并发下载。原文件上限为 512 MiB，不支持按字节续传。

工程内的“检查已下载原文件”图标可以重新验证已完成文件，分别报告检查通过、修复已排队和修复进行中的数量；检查通过的文件不会重复传输。

STAC 原文件传输前重新读取对应 Item，或按保存的 URL、方法及 JSON 请求体读取原始查询页面，核对条目身份、选定资产、属性和几何；若供应商已改变声明，需要刷新来源再选择。“原始条目元数据”中的“原始分页请求”可查看保存的请求。没有声明内容哈希的上游并不因此成为版本不可变存储：应用记录的是实际下载字节的哈希，不声称验证了供应商真实性。

工程可以同时包含原有供应商场景和自定义资产。自定义资产在任务内使用专门的类型，不进入 Sentinel SCL、反射率、雷达或高程处理分支。尚不支持的科学处理操作不会因文件扩展名或资产名称而启用。

## 原始信息与本地检查

原始目录响应与选中记录持久保存并校验内容哈希。离线检查必须重新验证受管原文件和保存的元数据。文件实际读取的尺寸、样本类型、通道数、坐标标签、NoData 和原始像元，与 STAC 声明的单位、缩放和偏移分别展示。显示用灰度拉伸不改变原始数据，也不自动应用物理单位换算。

不支持的压缩、布局、维度或投影应返回具体原因，原文件继续保留。不存在“下载通过即科学数据验证通过”的状态；原文件传输完整性、元数据声明、显示能力和科学处理能力是不同结论。

地图支持北向上的 EPSG:4326 / 3857、WGS84 UTM 和 NAD83 UTM 网格；其他坐标系暂保留元数据和原始行列取值。64 位整数超过 JavaScript 精确范围时，原值及 NoData 以十进制字符串保留，不经过浮点舍入。缺少 NoData 声明时，不把 0 自动当作无效值。

## CLI 示例

```sh
geod-runtime stac connect --request connection.json --data-dir workspace
geod-runtime stac search --request query.json --data-dir workspace
geod-runtime stac snapshot --id SHA256 --data-dir workspace
geod-runtime stac project --request project.json --data-dir workspace
geod-runtime stac download --request download.json --data-dir workspace
geod-runtime stac inspect --id JOB_UUID --data-dir workspace
geod-runtime stac pixel --id JOB_UUID --column 400 --row 600 --data-dir workspace
```

运行中的桌面或本地服务占用数据目录时使用对应服务入口；CLI 的 `--server http://127.0.0.1:4318` 可代替 `--data-dir`，不能让两个进程同时写同一目录。`stac download` 等待任务完成，失败退出非零。快照 ID 是 SHA-256，任务 / 工程 / 连接 ID 为 UUID。

请求文件分别使用原生字段：连接 `{ "name": "My catalog", "url": "https://…", "kind": "api" }`；查询含 `connectionId`、`collectionId`、`bounds` 及可选 `datetime` / `limit` / `cursor`；工程选择含 `snapshotId` 和 `assetKey`；下载含 `projectId` 和可选 `selections`。不接受在下载请求里自行替换原文件地址。

## 验收

2026-10-02，实际证据汇总见 [STAC / COG 验收记录](../prototype/qa/stac-public-verification.json)。测试使用独立本地目录，不修改用户已有工程。

| 路径 | 实际结果 |
|---|---|
| Earth Search API | 完整读取 4 + 4 + 0 三页共 8 个条目，保留终止空页；选择原始 `scl` 资产，完整下载 2,312,147 字节 |
| 独立 STAC Item | 保留与 API 一致的条目、属性、几何及资产声明；最终代码在传输前重新校验源条目，再下载同一 SCL；两份文件 SHA-256 相同 |
| 直连公开 GeoTIFF | 完整下载 3,765,647 字节 Copernicus GLO-90 文件；800 × 1200 Float32、EPSG:4326、Point 网格及半像元外边界与独立 GDAL 一致，未虚构 NoData 或观测日期 |
| 本地原值 | 两种不同原文件共 31,100,100 个样本由独立 rasterio / GDAL 全部解码；应用原始取值抽检共 17 次，其中 6 次为最终代码对同一 SCL 的复验，不声称全部像元已与原生读取器逐个比较 |
| 已完成文件复用 | 最终代码重新校验两种文件后返回原任务 ID；任务尝试次数、原文件字节和修改时间未变，没有重新传输 |
| 离线恢复 | 最终二进制运行 18 次独立 CLI，恢复 3 个连接、10 个快照、4 个验收工程和 3 个原文件任务；零外部网络请求，注册文件字节和文件哈希不变 |
| 界面 | 两种真实文件在 1440 英文浅色、1024 中文深色的项目、来源、地图和取值界面通过无头浏览器检查；未操作用户桌面，未把浏览器验收等同于已安装 WebView 人工验收 |

总计三次完整传输、8,389,941 字节，包含两种不同原文件。通用显示采用第一波段灰度预览，不启用传感器分类色板、物理校准或地形分析。原生工作区 316 项测试通过、4 项忽略，Clippy 无警告；前端全量检查通过 167 项逻辑测试和 159 项界面测试，最后的修复入口另通过 9 项 STAC 定向界面测试，最终前端构建通过。

另有一个明确保留的失败案例：官方 GLO-90 独立 Item 将集合链接指向另一公开 S3 区域主机，当前同源元数据策略拒绝连接。该案例未形成连接记录，也未下载原文件；这不是无日期 Item 的正向验收。WCS 独立接入状态见 [区域栅格说明](wcs-coverages.md)；跨主机元数据、MCP 自定义源接口及通用科学处理仍为待接入能力。
