# WorldCover Agent 参数交接修复 · 2026-10-17

## 原因

本机“我要土地利用的”会话已完成北京市边界定位和两幅 WorldCover 2021 原件的元数据归档。失败发生在方案准备阶段，尚未进入文件传输。

- 模型将连接编号作为工程选择参数，并将产品层名 `map` 当作原始资产键。
- `geod_stac_assets` 的参数名应为 `id`，模型使用了 `connectionId` 或 `snapshotId`。
- STAC 工程方案需要 `bounds` 与 `selections`；通用参数错误却附带了只适用于覆盖校验工具的“不要添加 bounds”提示。
- 反复变换错误参数耗尽了本轮 20 次操作预算。

## 修改

- 公开产品直接栅格的连接回执补充来自真实归档快照的资产键及可用性，明确后续工具与参数名，保持来源、年份、区域及原件选择不变。
- 按原生工具声明检查必要参数与未知字段。给模型返回实际声明的字段，不回显模型提供的私人值；原生值校验、场景约束和执行确认继续生效。
- 同一工具两次参数结构错误后停止该工具在本轮的继续尝试；下一轮重新计数。
- 只在覆盖校验错误中保留覆盖范围提示；普通参数错误不再要求删除必填区域。
- 新参数错误在界面显示为“工具参数不匹配，尚未生成方案”。已有历史回执不重写。

## 实际模型验证

使用当前桌面保存的 `deepseek-flash` 连接，在全新的独立测试目录执行自然语言请求，凭据仅在内存使用，未改写用户凭据或会话。

1. 请求北京 2021 年 ESA WorldCover 10 米土地覆盖，准备方案、不下载。
2. 模型完成产品目录、区域、连接归档与工程方案准备；工程未确认前没有项目或下载任务。
3. 测试程序仅在独立目录确认保存工程，再让模型准备原件下载方案。
4. 返回两幅原件的待确认下载方案，预计总量 221,798,791 字节（约 211.5 MiB）。保留真实原始资产键 `raster`，显示用资产类型为 `stac_asset`。

最终验收 15 条工具记录均成功；没有原文件传输，没有验证下载完成或后续裁剪出图。结果位于 `.verification/worldcover-agent-20261017/live-02/receipt.json`。
