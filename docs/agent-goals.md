# Agent 目标模式

2026-10-07。接入的是当前独立运行时 Codex 0.159.2 的真实 `thread/goal/set`、`thread/goal/get`、`thread/goal/clear` 接口，启用 `features.goals`。模型连接、数据处理和下载继续使用已有实现。

用户提出数据获取、处理或交付需求时，Agent 通过 `geod_goal_define` 保存完整目标、原始请求和必需成果清单。解释、问候和简单状态查询不创建目标。每个成果绑定本会话实际生成的原生计划，或者已完成且没有未读取分页的元数据查询。后续自动续跑不能删减或替换成果清单。同一个原生结果不能重复充当两项交付。

目标在对话中显示，展开可查看每项成果的状态，并可暂停、继续或清除。暂停不取消已经提交的下载；清除不删除工程、文件或后台任务。重启后保留目标和清单，恢复为暂停，等待用户继续。改变模型连接不能把目标转移到另一个账号或模型；原有同连接工具升级的历史恢复机制继续生效。

## 确认与持续推进

必要决策继续使用选项卡；答案不构成执行许可。下载和处理继续通过原生任务卡确认，或者遵循用户明确开启的自动执行权限。目标控制本身不改变执行权限，也不授权重试或取消。

Codex 原生 Goals 有自动续跑能力。GeoD 在最后一段模型响应结束前暂停原生目标，防止原生自动续跑与桌面监视器重复发起工作。已有单一监视器等待确认、必要选择或后台任务完成，再按实际执行权限唤醒同一 Codex 线程。每个目标最多连续续接 8 次；没有新的原生进展时停止并显示未完成。此上限是 GeoD 的续接限制，不是模型 token 预算或费用统计。

## 完成条件

完成后的再次复核在独立副本中检查全部原生计划与文件，全部检查结束后一次性发布目标状态。界面不会读到已验证成果编号被暂时清空的中间状态；复核发现真实失败仍显示未完成。复核过程中清除、暂停或重新绑定成果不会被迟到的检查结果覆盖。界面的快照刷新异常在下一次有效返回后消失，实际发送、确认和任务失败信息保持独立。

`geod_goal_check` 和回复结束后的自动检查读取最新计划与成果。只有所有必需成果通过检查，才写入原生 Goals 的 `complete` 状态。回复结束、方案获批、下载入队以及第一项成果成功都不能证明整个目标完成。

- 栅格：计划中的全部实际任务必须 `succeeded` 且 `settled=true`，再逐文件调用对应固定源、自定义 STAC、WCS 或科学 RGB 的原生检查工具。
- 矢量：保存结果必须存在，且最新 `geod_vector_inspect` 的 `verified=true`、文件 ID 和 GeoJSON 校验值有效；不套用栅格任务状态。
- 工程：核对实际保存的工程 ID；只证明工程元数据保存，不证明影像下载完成。
- 元数据：绑定本会话实际完成的原生读取，未穷尽的搜索分页不能作为完整元数据成果。
- 不可用能力、缺失成果、失败、取消、未收尾任务及已被替换的审核方案分别保留，不显示完整完成。

本次实现的是目标持久化、必需交付清单、原生结果聚合检查与受限持续推进。文件检查不代替科学准确性、完整有效覆盖或产品权限验收。清单中的区域、日期、科学处理等语义仍依赖原生预检、用户审核的方案和各产品已有适配；不宣称新增了通用科学分析执行器。

统一请求对象中完整的结构化区域、时段、质量与输出约束、多区域长时序批次、检查点续跑、通用重投影和统计 CSV 仍按[类别规划](../GeoD-Global-Spec/15-General-Agent-Tasks.md)推进。

## 本轮验证

真实独立 Codex 进程已验证原生 Goal 设置、读取、暂停、重启恢复、完成和清除。模型响应使用私有回环受控数据，不调用用户的模型账号，不产生地理数据下载；成功响应和受控失败各发出一次模型请求，均在回复或错误结束前暂停，未出现双重续跑。

目标契约、会话恢复、审核等待、逐文件检查、无进展停止、私有控制和界面检查分别记录。受控结果不称为真实模型自然语言下载验收；本轮没有新打包或发布。记录见[目标模式验证](../prototype/qa/agent-goals-verification.json)。

官方接口依据：[OpenAI App Server](https://learn.chatgpt.com/docs/app-server)、[Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)。生成的接口契约来自本仓库拥有的固定版本二进制。
