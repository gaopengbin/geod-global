## 实际完成的流程

在独立会话输入明确需求：数据云产品 `421`（GDEM V2），WGS84 范围 `[116.2,40.1,116.4,40.3]`，时间条件 1980-01-01 至 2026-10-15，选择可用的 `ASTGTM2_N40E116` 原件；先确认，后下载，完成后核验并展示。保留原件，不裁剪、不拼接、不更换来源，不提交预约或采购。

1. 模型调用真实数据云目录、检索和详情，命中所需瓦片。
2. 原生端保存当前会话专属的检索回执，生成带有不可变哈希和 30 分钟有效期的方案。确认前本会话新增任务为 **0**。
3. 测试操作者在界面的“确认下载”卡片上点击确认，原生端重新核查条目可用性与产品范围，再通过已连接的数据云账号下载。账号信息未进入模型或前端参数。
4. 本会话创建 **1** 个真实下载任务，下载结束后原生监视器自动继续会话，模型核查任务和原件，完成目标。
5. 右侧成果面板实际展示 ZIP、文件清单、大小、校验说明和“打开文件夹”入口；前端已确认收到并显示该成果。

## 权限与重复执行

- 新增模型工具为 `geod_gscloud_download_plan` 和 `geod_gscloud_archive_inspect`。模型不能提供下载网址、账号、密码或自称批准方案。
- 下载方案只能选同一会话、有效期内的真实检索回执所列可用条目；单次最多 4 个原件。跨会话、过期、重复 ID、未接入产品和预约条目均被拒绝。
- 执行复用既有确认/自动执行权限与原生方案哈希；原生队列以方案派生的任务 ID 防止重复创建。
- 成果目标新增 `archive` 类型，完成检查核验整个方案的全部 ZIP，使用归档检查器，不会调用 TIFF 解码器冒充包内栅格预览。
- 重复确认补测发现旧的会话调度会再次唤醒模型，虽然未重新下载，仍产生重复回复。已给确认事件增加去重，已记录的原生执行回执不再添加会话事件或重新登记后台监视。
- 使用更新后的 Agent 包重启后，连续重放同一确认两次：新增任务 **0**、新增模型请求 **0**、新增会话事件 **0**；会话和原件清单仍可重新打开。
