# GeoD Global 0.2.4

- CBERS WPM now disables unsupported first-year acquisition months. Selecting 2019 clears an incompatible month and requires an explicit new choice; the application never silently substitutes a different acquisition date. A previously accepted 2019-10 form was reproduced returning HTTP 400 locally in 263 ms because this collection starts in December 2019. This fixes that reproducible rejection path, not a claim that all 26 historical anonymous failures had that cause.
- CBERS WPM previews now read a verified downloaded original band locally. The tested original is a striped TIFF without overview levels; it is not treated as a fast online COG. Before downloading, the UI clearly requires the original and does not mark a range-preview layer as visible. After explicit download confirmation and file validation, its native map and original pixel read are available.
- Public downloads waiting to retry now show queued state while waiting for a worker slot. The first source bytes have a 45-second deadline after admission; the existing two-retry limit, cancellation, verified resume and ongoing-data inactivity deadline remain. Healthy large downloads are not capped by total elapsed time.
- Public-product failures distinguish service requests, response decoding and contract validation while retaining available HTTP status. Existing fixed diagnostic codes are reused; raw errors, coordinates, paths and URLs are not sent.
- Projects, model settings, acquisition attribution and downloaded originals remain compatible with the prior release. Windows updates remain signed and require user confirmation.

## 中文

- 修正 CBERS WPM 可选年月与原生产品范围不一致的问题：2019 年仅允许选择 12 月；原月份失效时留空，由用户明确重选。
- CBERS WPM 使用“确认下载原始波段 → 校验 → 本地地图预览”的路径。完整原件尚未下载时，不再尝试不稳定的在线整景读取。
- 修正下载重试等待并发名额时仍显示“进行中”的状态。公开下载获得名额后，最多等待 45 秒接收首批文件数据；保留取消、有限重试与校验后的断点续传。
- 细分公共产品的请求、内容解析与返回数据校验失败，保留可用的 HTTP 状态，不上传原始错误或敏感信息。

See `docs/operations/first-use-reliability-20261028.md` for the investigation and evidence limits. Final package hashes and installation/update acceptance are recorded separately; a successful current CBERS test cannot reconstruct missing historical request parameters.
