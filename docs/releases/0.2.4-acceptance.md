## Confirmed defects and limits

- A real UI request for CBERS WPM October 2019 was locally rejected with HTTP 400 in 263 ms, before upstream discovery. The form now disables unsupported first-year months and clears an incompatible month instead of silently substituting one.
- The tested original has one-row TIFF strips and no overview levels. An online preview reported visible in the test while its canvas had no actual raster pixels. CBERS now explicitly downloads and validates the complete selected original before local preview. Before download, preview is disabled with an actionable prerequisite; it never initiates an undeclared whole-file preview transfer.
- A retry waiting for a worker slot no longer retains its previous running state. Reviewed public downloads have a 45-second first-data budget after admission, followed by the existing inactivity guard. Cancellation, bounded retries and verified resume remain. This does not impose a total-duration limit on healthy large transfers.
- Service requests, response decoding and response validation have separate fixed diagnostics. Available HTTP status is retained without uploading raw errors, source URLs, coordinates or paths.

The historical 26 CBERS failures did not include requested dates, so they cannot all be assigned to the reproduced month bug. Likewise, the old zero-byte event's elapsed bucket included queue time and its exact network cause is unavailable. The release fixes reproduced defects and bounds waiting; it does not invent historical diagnoses. See the [investigation](../operations/first-use-reliability-20261028.md).
