# Sentinel-1 IW RTC 工程裁剪与拼接验收

2026-10-02。工程页已接入 RTC 单景裁剪，以及同极化、同坐标系、同分辨率且像元原点对齐的多景拼接。输入是供应商已生成的 RTC 产品；这里的处理不执行原始 GRD / SLC 定标、地形校正或散斑滤波。[原文件与来源边界](radar-inspection.md)

## 数据规则

- 输出保留单波段 Float32 线性 gamma0、原始 10 米 WGS84 UTM PixelIsArea 网格及 VV / VH / HH / HV 极化标记。处理和检查均不把 dB 显示值写回成果。
- 0 是有效强度；-32768 是 NoData。重叠处按工程中已排序的日期取较新景的有效值，较新景的 NoData 不覆盖旧景的有效值；不求平均。
- 矩形工程区域在源坐标系中取完整像元包络。保存的 WGS84 多边形按输出像元中心是否处于原多边形内判断，支持孔洞；孔洞、边界之外及未覆盖区域设为 -32768。
- 每份来源绑定任务 ID 和 SHA-256。处理前完整核对原文件，拒绝改变后的文件、极化混用、未对齐网格、负强度、NaN 和无穷值。取消不发布临时成果。
- 输出内嵌极化、`gamma0 (linear)` 单位和产品标记，附带来源及网格清单。输出全部样本重新解码核对后才记录成功；显示和像元查询继续核对成果的完整 SHA-256。
- 分条带处理使用受限内存，必要时写 BigTIFF。已用 900 万个合成 Float32 样本验证跨条带逐位保留；这项测试不代表对应大小的生产影像已验收。

核对工具使用 GDAL/rasterio 解码实际原文件与成果，使用 PROJ 将成果像元中心转换回 WGS84，再由 GEOS/Shapely 独立判断多边形及孔洞。只转换顶点后在 UTM 连接直线会改变 WGS84 边线，因此不能用来替代本项验收。三份成果共核对 6,685,308 个原始 Float32 位模式，另外检查各成果的三个原生像元查询、空间信息、内嵌极化和单位、来源清单、预览与缩略图。[独立验证工具](../scripts/verify-radar-processing.py)

三份实际成果均通过只读连接进入前端工程与工作空间地图；无头浏览器覆盖 1440 宽英文浅色和 1024 宽中文深色，无页面错误或横向溢出。该测试未操作用户桌面，不替代安装版 WebView 验收。[精简验收记录](../prototype/qa/radar-processing-verification.json)

原生服务实际重启后，三份成果的空间信息和九个像元查询保持一致，缩略图再次命中持久化缓存，内容哈希不变。本机开发模式下命中约 6–35 毫秒；这不是发布版性能承诺。

## 仍需推进

本页处理成果验收覆盖上述两份 VV 输入和三个区域成果。极化扩展已完成第一份完整 VH 原件的校验、原值、预览、只读 MCP 和生产前端显示；另一个 VH 单景区域的 40,096 个成果值与来源逐位一致，实际处理按钮及成果 MCP 取值通过。其余 VH / HH / HV 原件及完整九份成果矩阵继续验收，见[极化扩展进度](radar-polarizations.md)。跨 UTM 分区和重投影、时间序列分析、分类、滤波以及原始 GRD / SLC 处理仍未验收或未实现。供应商 RTC 的地形校正精度没有在此独立评估。NASA / Copernicus 的软件内授权入口已保留，账号授权后的生产原文件验收仍待推进。
