# Maxar / Vantor disaster open imagery — 2026-10-12

Two actual **Maui 2023 analytic originals** pass the existing generic STAC workflow: unchanged metadata and matching acquisition collection, fresh complete downloads, independent whole-grid decoding, native previews and raw values, and an isolated restart. The finite `maxar-open-legacy` adapter and parent-owned shared hooks have been implemented; final built-in preset and UI acceptance remain pending with the parent task. **The new 2026 Vantor visual channel remains planned**, because its actual JPEG/YCbCr encoding is not decoded by the current native raw-sample reader. [Detailed evidence](next2-maxar-20261012.json).

## Actual catalogs and discovery

The [publisher program](https://vantor.com/company/open-data-program/) and [AWS registry](https://registry.opendata.aws/maxar-open-data/) describe disaster-event releases with attribution and noncommercial-use restrictions. These are event archives, not global on-demand free imagery, a commercial purchasing service or a GeoD Pro commercial-use entitlement. The [publisher asset guide](https://xpress-docs.maxar.com/OpenData/OpenData_viewing.htm) distinguishes multispectral/panchromatic analytic imagery from 8-bit visual products.

Community discovery was useful: a [remote-sensing discussion](https://www.reddit.com/r/remotesensing/comments/1stmw46/did_maxar_vantor_stop_publishing_open_data/) points to the new bucket, while [OpenGeos' older index](https://github.com/opengeos/maxar-open-data) and [Vantor visualization project](https://github.com/opengeos/maplibre-gl-vantor) show alternatives for browsing and display. Their claims were checked against actual publisher requests; no community mosaic or derived geometry replaced publisher metadata.

Both public catalogs returned HTTP 200. The [legacy Maxar catalog](https://maxar-opendata.s3.amazonaws.com/events/catalog.json) still contains ARD events. The [new Vantor catalog](https://vantor-opendata.s3.amazonaws.com/events/catalog.json) contains **11 2026 event collections**, including Nepal flooding, Spokane wildfire and Mexico Hurricane Simon. Anonymous root listing also exposes the publisher's [bucket license](https://vantor-opendata.s3.amazonaws.com/LICENSE.TXT), which states CC BY-NC 4.0. Four actual new event documents were retained; item/collection licenses matched for the reviewed Nepal event. Screening 69 same-basename TIFF candidates found 29 within 512 MiB, but screening alone is not acceptance: actual item asset declarations were checked before downloading.

## Mask and display boundary

Both analytic originals have **no scalar NoData tag**. Rasterio reports a `per_dataset` validity mask. The mask is a separate second IFD (index 1, photometric 4) plus reduced mask IFDs; it is not a SubIFD or alpha channel. These original masks remain in the complete files, while the current native first-band grayscale preview and scalar `noData` flags do not apply them.

The difference is verified, not hypothetical. For multispectral `(0,0)`, all eight raw values are zero and all native `noData` flags are false, but the independent file masks are all invalid. At footprint-interior `(1449,2452)`, native values `[95,296,469,512,524,1158,1741,1925]` match Rasterio, with the original masks valid. Panchromatic `(0,0)=0` has scalar `noData=false` and mask invalid; footprint-interior `(5799,9809)=470` has scalar `noData=false` and mask valid. Ten native coordinate readouts matched the original samples and scalar NoData across the two supported files.

The MS mask marks 742,179 first-band pixels valid, and the pan mask marks 11,858,587. Those are whole-file mask counts, **not valid-AOI coverage or cloud-quality results**. The file canvas covers a full 5.3125 km tile and includes areas beyond the smaller acquisition footprint. Map bbox intersection, a raw zero, scalar `noData=false`, scene cloud metadata or the grayscale preview does not establish useful area coverage or disaster damage. The adapter includes that limitation in its visible source warnings.

## Explicitly unsupported visual products

The selected Maui item also declares `visual` and GeoPackage `data-mask` assets. Their original declarations remain intact. A fresh native download of the complete 10,420,319-byte visual TIFF and an independent decode of all 909,115,392 RGB samples succeeded, but its JPEG/YCbCr photometric interpretation 6 is outside the current raw decoder. Native inspection returns accurate metadata with no preview and a decoding limitation; raw pixel access returns HTTP 400. It is not a supported adapter layer. The GeoPackage is not accepted as raster imagery.

The independently tested new Vantor [Nepal item `B120001101250A10`](https://vantor-opendata.s3.amazonaws.com/events/Nepal-Flooding-Aug-2026/B120001101250A10.json) declares a visual asset and matches its event collection. Its full original was freshly downloaded twice through separate research/native paths: **29,534,465 bytes**, SHA-256 `54833b631a8e999ccb6b2aebd409648f79d2a4ece60041b94978aeec009c6f3a`. Rasterio decoded all **4,492,986,219 visual samples** of the 36,389 × 41,157 × 3 UInt8 EPSG:4326 grid. Native behavior preserves the format guard: metadata is readable, preview is absent, and raw pixel access rejects decoding. Restart preserved its original, metadata, project and guard. This is a planned visual-decoder requirement, not a ready data channel.

That new item was observed on **2026-09-07**, despite its event's August label; publisher cloud cover is 93%. Its full IFD structure has the main image and seven reduced overviews, with no scalar NoData tag, dataset mask or alpha. A TIFF helper's convenience `nodata` default of zero was corrected against actual tags and Rasterio; no zero mask was fabricated. A second independent new-Vantor GET timed out after 42,991,616 of 51,775,473 bytes and was quarantined as an unaccepted partial file; a third was not attempted. A separate Python Maui visual GET truncated and was likewise rejected, although the native transfer completed correctly. These failures remain recorded rather than being counted as downloads.
