# 本地 GeoPackage 矢量文件

2026-10-03。“我的数据 → 矢量文件”现支持独立 `.gpkg` 文件的引用或明确复制、完整来源核验、多图层地图、原始属性查看和离线导出。桌面、受保护的本地服务与 CLI 共用同一个读取器；应用运行不要求安装 GDAL。

## 打开、查看和导出

桌面文件选择器默认引用原文件；选择“复制到 GeoD 数据目录”时保存完整数据库副本。开发浏览器的“导入矢量副本”上传实际文件字节，只提供受管复制，不把文件名当成本机可持续访问的路径。登记与完整 SHA-256 持久保存，每次查看和导出重新核对来源，并检查重新转换的内容与登记一致。

工作空间的图层选择器可以显示全部图层或指定要素表，缩放只使用当前可见图层的范围。点击地图显示来源表、原要素编号、全部属性和原始 M 值；切换图层清除旧选择。无几何、空几何或空集合仍保留在导出数据中，不制造地图位置。

两种导出明确分开：GeoJSON 是转换后的 EPSG:4326 数据，附带来源、图层、字段和转换记录；“导出原始 GeoPackage”核对后复制原数据库字节。原件中非空间表、瓦片、空间索引和扩展内容随原文件保留，当前不作为矢量图层解释或呈现。软件不修改原件，不因格式推断数据许可，也不宣称获得 OGC 兼容认证。

## 当前读取范围

读取器支持 GeoPackage 1.2–1.4 中的普通要素表，以及核心的 Point、LineString、Polygon、MultiPoint、MultiLineString、MultiPolygon 和 GeometryCollection。依据容器的几何头、SRS、维度和实际 WKB 检查大小端、包围范围、Z / M、空几何与完整消费。多部件中的空成员保留；需以 GeometryCollection 表达时记录原几何类型。[GeoPackage 几何编码](https://www.geopackage.org/spec/#geometry_encoding)

原始整数主键作为要素编号保留。超出 JavaScript 安全整数范围的编号和整数属性转为十进制字符串，避免浏览器将其舍入；BLOB 属性使用 Base64，字段元数据记录转换方式。其他 SQLite 属性值、空值及字段的原声明类型保留。Z 原值不做垂直基准或高度转换；M 独立保存为 `geodMeasures`，不冒充高度，M 的 NaN 按无数据转换为 null。GeoJSON 的 `geodLayer` 区分来源表。

每份原文件和转换后的 JSON 各限 20 MiB，合计最多 50,000 个要素、500,000 个坐标、32 个要素图层及 32 条其他内容记录；每个要素表最多 128 列，包含主键和几何列。SQLite 以只读内存副本读取，限制查询资源，仅访问普通来源表；不运行用户 SQL、触发器、外部函数、虚拟表或扩展。只接受独立数据库文件，不读取 WAL / SHM 旁文件，生产工具应先正常关闭并导出独立 GeoPackage。

## 坐标转换与精度边界

同时保留来源 WKT、可选 WKT2、声明的机构 / 编号、实际用于转换的坐标定义和水平基准操作。EPSG 编号与 WKT 的语义冲突会报错；缺少必要网格、不支持的轴方向或不可用的操作也会报错，不自动下载坐标转换资源。GeoPackage WKB 的 XY 按规范是经度 / 纬度或东向 / 北向，优先于 WKT 中可能相反的轴序；适配后的定义另行记录，原 WKT 保持不变。[XY 顺序规则](https://www.geopackage.org/spec/#gpb_format)

地图与 GeoJSON 的水平坐标转换到 EPSG:4326，包括源投影的逆变换及所选基准操作。元数据中的 `Identity` 表示基准操作为恒等变换，不表示 EPSG:3857 / UTM 等投影坐标未经转换。**目前每个图层使用一个固定、可记录的基准操作，并不按每个坐标所在区域动态选择最优方法。** 操作有声明范围时统计超出范围的坐标，在工作空间明确提示，声明精度只在该操作适用范围内有意义。

实际 OGC 美国县样本的 NAD83 图层使用 `EPSG:1188 — NAD83 to WGS 84 (1)`，声明精度 4 米；181 个坐标超出其适用范围，不能套用 4 米精度。独立复核明确采用这一已记录方法，全部 XY 数值的最大差异为 `9.43245481721533e-10` 度。另与 PROJ 自动选择区域方法比较，最大差异为 `8.275546157676672e-6` 度；二者是不同方法，这个差异不应被隐藏或解释成生产坐标绝对精度。原始坐标仍完整保留在原 GeoPackage 中。

## 验收证据

采用一个公开生产者样本和一个独立生成的测试文件，来源分别记录：

| 输入 | 原文件 | 独立核对 |
|---|---|---|
| [GeoPackage 实施指南列出的 sample1_2.gpkg](https://www.geopackage.org/data/sample1_2.gpkg) | 2,322,432 字节；SHA-256 `d6bf8dc8972e94e08b017c018d773cf9f4a44403e652f105ca90d02b6ffba842` | 3,141 个县要素、83,859 个坐标、31,410 个属性值；EPSG:4269 与缺少内嵌机构编号的 ESRI WKT、原非空间表及完整原文件 |
| GDAL 3.9.2 独立生成的控制文件 | 184,320 字节；SHA-256 `a65fdcee8a141bf841fef550bc62f25170482a69aa8fa05a7ffd64668afcaa47`；明确是测试文件，不是供应商交付 | 5 个图层、8 个要素、43 个属性值；EPSG:4326 / 3857 / 32633、Z / M、孔洞、集合、NULL / 空几何、中文文本、超大整数主键、BLOB 和其他内容；41 个数值最大差异 `2.842170943040401e-14` |

两份输入分别在实际原生 CLI 中引用和复制，所有原文件导出保持字节一致。GDAL 读取全部源几何，SQLite 读取全部原属性，pyproj 复核明确记录的操作；没有以本产品转换器作为参考答案。

独立控制文件冻结于 `crates/geod-runtime/fixtures/geopackage/independent-ogr.gpkg`，来源、生成工具和 SHA-256 记录于同目录 `SOURCE.json`，原生回归直接读取这份实际 OGR 编码。QA 生成脚本 `scripts/generate-geopackage-fixture.py --out NEW_FILE.gpkg` 使用 GDAL 创建新文件，不覆盖原件；不同生成时间或 GDAL 版本的 SQLite 字节可能不同，不能将新生成文件假定为同一哈希。脚本已实际重跑，最新开发程序导入 / 导出新生成文件后，全部 8 个要素与 43 个属性再次由独立工具核对，并读回旧 OGC 受管记录。

无头浏览器实际导入原字节，在 1440 像素英文浅色及 1024 像素中文深色下检查真实地图、5 图层切换（含名为 `all` 的表）、点击属性和 M、完整双格式下载、面板拖动、来源详情和超出转换范围的提示。来源详情已修复多层嵌套造成的极窄列，展开后不产生横向溢出。页面无异常，未请求远端目录或在线底图。该检查未操作用户桌面，不代表原生文件选择器、保存对话框和安装版 WebView 已人工验收。

实际停止和重启原生服务、移走测试输入、启用拒绝连接的代理后，5 份受管副本均重新进行完整独立核对，原文件导出一致；两份丢失输入的引用登记明确报错，不静默改成受管副本。

机器可读摘要见 [GeoPackage 验收记录](../prototype/qa/geopackage-local-verification.json)。重跑独立核对：

```powershell
python -X utf8 scripts/verify-geopackage-local.py --source SOURCE.gpkg --export EXPORTED.geojson --original-export ORIGINAL.gpkg --registry DATA/vectors.json --id UUID --report REPORT.json
```

脚本的 GDAL / pyproj 仅是 QA 依赖。CLI 使用 `vectors open --file FILE.gpkg --data-dir DIR`（默认引用）或显式 `--mode managed`；`vectors export --id UUID --out FILE --format geojson|original --data-dir DIR` 区分转换数据与原件。直接模式可以使用明确的本机路径，HTTP 仅提供有界文件字节导入和当前登记的原文件读取，不接受任意本机读写路径。
