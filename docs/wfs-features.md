# WFS 2.0 矢量服务

在“我的数据 → 矢量文件 → 获取矢量数据”选择 **WFS 2.0**，输入公开 HTTPS 服务地址或 GetCapabilities 地址。连接后可搜索要素类型，选择服务声明的 GML 3.2 或 GeoJSON 格式，按当前探索区域提取，并保存为本地矢量文件。连接可以刷新或移除；移除连接保留已有文件。界面沿用现有共享组件和中英文设置。

这是公开 WFS 要素服务适配。NASA Earthdata / Copernicus 软件内授权入口独立保留；没有账号的受保护原文件仍待实际授权验收。

## 查询与坐标

服务须声明 WFS 2.0.0、GetCapabilities / DescribeFeatureType / GetFeature 的 GET 入口，以及至少一种支持的响应格式。软件仅请求用户配置的地址，不跟随能力文档中的其他主机、外部模式文件或要素链接。不能使用的要素类型会列出原因，不推断访问权限或数据许可。

按 WGS84 外接矩形查询完整要素，另外记录用户选中的多边形；不在下载时隐式裁剪、不请求几何简化或降低精度。请求的 EPSG:4326 URI 使用纬度、经度轴顺序，GML 在本地转换为 GeoJSON 经度、纬度顺序。GeoJSON 按其格式的经度、纬度语义读取。服务若不支持所请求的坐标系或返回无法确认轴顺序的 GML，会明确失败。坐标处理遵循 [OGC WFS 2.0 标准](https://www.ogc.org/standards/wfs/)和[GeoServer 轴顺序说明](https://docs.geoserver.org/main/en/user/services/wfs/axis_order/)。

GML 支持二维点、直线、带孔洞多边形、多部件和几何集合；由相接直线段组成的 Curve、单个平面 PolygonPatch 可以无近似地转换。弧线、曲面、多几何字段、三维 / M 轴、外部引用、复杂或重复属性拒绝导入，不将它们静默简化。属性须有对应的 DescribeFeatureType 声明，保留可选字段缺失与显式空值的区别。

字段记录名称、基础 XMLSchema 类型、是否可空和可缺省。布尔与安全整数转为相应 JSON 类型；大整数和 decimal 保留为字符串，避免 JavaScript 精度损失。浮点值须有限，文本与日期文本不改成展示格式。原始 XML 仍完整保存在本地；派生 GeoJSON 不是 XML 逐字符复制，也不是完整 XSD 验证器。格式差异见 [GeoServer WFS 输出格式](https://docs.geoserver.org/main/en/user/services/wfs/outputformats/)。

## 完整性与原始响应

提取前获取字段定义和数值匹配数量，按固定的 startIndex / count 参数分页；每个要素必须有原始编号，页内及跨页重复、空页、数量不符均使整个提取失败。未声明分页的服务只接收单页完整结果。

随后用相同参数完整读取第二遍，比较所有属性、几何和成员，并再次核对匹配数与字段定义。存在非空且必填的整数 `id` / `fid` / `objectid` 字段时，按该字段升序读取并检查唯一性；此时允许服务临时生成的 GML 编号变化，但保留第一遍原始编号。没有稳定字段时，两遍原始要素编号也须一致。字段定义比较保留限制项及命名空间绑定，排除仅布局空白、注释和属性次序变化。

这些检查能够发现两遍之间的变化，**不等于服务器提供事务一致快照**。响应时间也不是数据观测日期，不填入文件的观测时间。

受管文件格式为 `wfs-snapshot`：保存前后完整字段定义、计数响应及两遍所有原始 UTF-8 响应。每份文档都有准确 URL、字节数和 SHA-256；文件的 sourceSha256 是归档本身的校验值，geojsonSha256 对应派生 GeoJSON。打开及导出时重核归档和每份文档，再执行同一转换与一致性检查。来源信息随导出的 `geodSource` 保留。

单次提取最多 5 万要素、每遍 250 页、每页 200 个、两遍与元数据合计 20 MiB 响应、180 秒网络处理；保存归档另限 20 MiB，转换结果最多 50 万坐标。能力发现限 8 MiB。所有验证完成后原子保存，失败不登记部分文件。网络使用软件设置中的跟随系统 / 直连 / 自定义代理。

## 复验与当前边界

2026-10-02 的[实际验收记录](../prototype/qa/wfs-features-verification.json)包含以下 5 份本地档案，均由运行中的 Rust 核心提取并由独立 XML / JSON 解析及 GEOS 核对：

| 公开服务 / 编码 | 完整要素 | 坐标位置数 | 每遍页数 |
|---|---:|---:|---:|
| MapServer 城市 / GML | 1 点 | 1 | 1 |
| MapServer 大陆 / GML | 3 面 | 4,879 | 2 |
| EMODnet 海岸线 / GML | 1 线 | 8,929 | 1 |
| 同一 EMODnet 海岸线 / GeoJSON | 1 线 | 8,929 | 1 |
| MapServer 城市 / GML，每页 1 个 | 7 点 | 7 | 7 |

合计 22,745 个坐标位置与 1,126,765 字节归档。表中的重复区域和不同格式不是不同地物计数。全部原始编号、属性、几何、查询框外完整坐标及双遍回执核对一致；真实面样本没有孔洞，孔洞和复杂多部件目前只有合成回归测试。MapServer 无编号的 GeoJSON 已实际触发明确拒绝，未改变已有登记或留下源文件。

更新后的原生程序通过 12 次独立 CLI 启动，在零网络请求下恢复两条连接、检查并导出全部 5 份档案；原档、每份响应及导出校验值不变。既有 5 份 Overpass、6 份 ArcGIS 和 8 份 OGC 档案也完成离线回归。

5 份 WFS 档案均在无界面 Chromium 中验证了英文浅色 1440 像素和中文深色 1024 像素界面，包括地图选点、原始属性、来源及精确导出。过长的服务介绍默认折叠，提取按钮在初始视口可见。没有操作用户桌面；Windows 安装版 WebView 尚未人工验收。本轮不生成发布包。

真实公共服务验收脚本为 [verify-wfs-public.py](../scripts/verify-wfs-public.py)，仅对显式指定的服务发起只读提取，使用独立数据目录；可以直接检查已有 asset，避免重复访问服务。脚本从保存的原始响应独立解析几何、孔洞、字段值、编号及轴顺序，并核对导出和每份响应回执。

停止隔离服务后，可用 [verify-wfs-restart.py](../scripts/verify-wfs-restart.py)从既有真实报告复验离线恢复和导出，不重新请求上游。工程检查包括 29 项 WFS 专项、295 项原生工作区测试、161 项 Node 测试、153 项界面测试及前端构建；runtime / desktop 严格 Clippy 通过。

CLI 复用 `feature-services connect|query` 与 `vectors inspect|export`。连接请求的 `protocol` 为 `WFS2`；查询可选 `responseFormat: "gml32"` 或 `"geojson"`，省略时优先 GML 3.2，`pageSize` 为 1–200。原 OGC / ArcGIS / Overpass 连接及文件无需迁移。

仍待支持：WFS 1.x、账号 / 内网连接、服务别名或跨主机操作地址、复杂要素与完整 XSD 验证、曲线 / Z / M、其他投影、属性 / 时间过滤、事务编辑、取消 / 续取、超限区域分片、精确裁剪及工程内矢量处理。部分服务的 GeoJSON 没有原始要素编号，这类响应会提示选择 GML，不生成编号冒充原始标识。
