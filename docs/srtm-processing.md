# SRTMGL1 工程裁剪与拼接

2026-10-02。工程内所有 SRTMGL1 v003 原始 HGT ZIP 下载完成后，可按已保存区域裁剪单瓦片，或拼接并裁剪多个瓦片。原包保持不变，结果归入同一工程，并可在工作空间显示、读取像元和缓存缩略图。当前没有真实 Earthdata 测试账号，以下处理证据均来自明确标注的合成输入；不是 NASA 原文件下载或地形精度验收。

## 输出规则

- 每个原始瓦片为 3601 × 3601 点，间距 `1/3600°`。相邻原点相隔 3600 个采样间距，共享边缘占同一输出行 / 列；两块横向相邻的完整网格为 7201 × 3601，纵向相邻为 3601 × 7201。
- 输出保留单波段有符号 Int16、WGS84 水平参考、EGM96 高程基准（EPSG:5773）和 PixelIsPoint。高程单位为米，0 和负值有效；仅 `-32768` 为 NoData。空隙、原始缺失值及多边形掩膜保留此值。
- 来源按目录参考日期、瓦片 ID 升序排序，后一个有效值覆盖前一个；后一个 NoData 不覆盖已有有效值。参考日期不被解释为每个瓦片的实际观测时间。
- 裁剪范围向外取整到原始网格；仅对浮点计算误差接近整数的边界作对齐。多边形按原始像元中心判断覆盖，没有重采样、重投影或垂直高程转换，也不混合 GLO-30 的 EGM2008 / Float32 数据。
- 文件采用 Deflate 压缩的 GeoTIFF 1.1，使用 Point 采样位置及垂直 CRS / 米制单位键。GDAL 默认可以报告 WGS84 + EGM96 复合参考（EPSG:9707），不需要额外开启 GeoTIFF 1.0 的垂直参考报告选项；见 [GDAL GeoTIFF 说明](https://gdal.org/en/stable/drivers/raster/gtiff.html)。软件地图仍用水平 EPSG:4326 定位，并单独明确 EGM96 高程基准。

## 处理与完整性

处理前校验每个受管原包的完整字节数、SHA-256、瓦片身份、HGT 条目长度与 ZIP CRC。在 Windows 上持有同一原包的只读文件句柄，处理期间防止替换。HGT 解码为工作空间内临时大端原始字节，不生成中间 TIFF；每个瓦片暂存约 25.9 MB，逐个解压后释放内存。128 行源块及有界输出条带复用既有处理引擎，支持超过八百万像元的项目。处理结束、失败或取消后自动清理暂存文件。意外退出后，启动时在工作空间独占锁下回收引擎专属名称的 HGT 暂存文件，不清理其他文件；恢复测试覆盖专属暂存回收及无关文件保留。

编码后逐条带重新读取并比较像元哈希，核对 Int16、Point、EGM96、网格、NoData 和覆盖计数，再原子提交结果及来源记录。持久化记录绑定原包任务和哈希。取消任务不会公开未完成文件，不能用缩略图代替科学原值校验。导出 TIFF 不是带在线随机访问优化的 COG。

## 验证

- 实际隔离 Rust 运行时读取两张合成 HGT 原包，生成 7201 × 3601 GeoTIFF；独立 Rasterio / GDAL 解码并逐值比较全部 **25,930,801** 个像元。四个边缘样本覆盖有效零、正负极值与 NoData；两个原包哈希未变。
- 同一运行时生成 3 × 4 多边形裁剪结果，12 个像元全部核对，4 个掩膜像元为 `-32768`。
- 原生测试另覆盖完整纵向共享边缘、NoData 重叠回退、源篡改、启动前取消、HGT 暂存完成后取消和临时文件清理。
- 实际停止并重启隔离运行时，派生结果的空间元数据、边缘像元、PNG 和缓存内容 / 文件身份均未变。缓存命中仍按 LRU 策略更新修改时间。
- 明 / 暗 1440 × 940、紧凑 1024 × 940 无头界面验证工程处理入口、HGT 卡片打开工作空间、派生 TIFF 地图、原值读取和中文说明。未操作用户桌面。
