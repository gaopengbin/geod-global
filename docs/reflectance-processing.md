# Landsat / HLS 原始波段工程处理

2026-10-01，工程页已接入红、绿、蓝单波段的区域裁剪及同网格多景拼接。每个波段独立生成 GeoTIFF，保留原始整数 DN；这里的拼接不会合成 RGB 或修改反射率值。

| 产品 | 输出类型 | NoData | 输出反射率转换 |
|---|---|---|---|
| Landsat 8/9 Collection 2 Level-2 | UInt16 | 0 | `DN × 0.0000275 - 0.2` |
| NASA HLS L30 v2.0 | Int16 | -9999 | `DN × 0.0001` |

## 操作及输出

在「我的数据 → 工程」下载所需波段，全部选景的该波段就绪后，点击「裁剪到工程区域」或「拼接并裁剪」。任务复用已下载文件，不重新下载。处理结果仍归入当前工程，可通过「处理结果」筛选、打开工作空间、检查栅格或读取像元。结果卡片显示波段及处理类型，不重复长工程名。

输入必须来自同一受支持产品版本、同一通道、同一 UTM 坐标系及对齐的 30 米网格。文件中的采样类型、空间标签、NoData 和已记录 SHA-256 都要通过校验；不同产品的校准参数、不同网格或已改变的源文件会被拒绝。32 景上限沿用工程约束。

输入按采集时间和影像 ID 排序，较新的有效 DN 覆盖较旧值；较新的 NoData 不覆盖已有有效值。HLS 的零值和负值仍有效。工程矩形向外对齐到完整源像元；选用多边形时，按像元中心判断，将边界外像元设置为该产品的 NoData。矩形本身是源坐标包围窗口，不声称精确的经纬度多边形遮罩。

输出按最多 512 行的条带写入 Deflate GeoTIFF，并对完整输出进行解码回读、像元字节比较及 SHA-256 校验。像元、覆盖及压缩缓冲合计遵守 64 MiB 的条带预算，源解码另有分配限制。磁盘空间不足或取消时不提交成功结果。此单波段处理步骤不做重投影、重采样或 QA / Fmask 质量掩膜。匹配的红、绿、蓝成果可另行组合并生成[科学 RGB 文件](scientific-rgb.md)。

PixelIsPoint 输入先换算成外边界。结果使用 PixelIsArea，保持同一像元中心和 DN，避免 Landsat 半像元偏移。NoData 写入 TIFF 标签 42113；scale / offset 写入 [GDAL GeoTIFF 元数据标签 42112](https://gdal.org/en/stable/drivers/raster/gtiff.html)，GDAL / Rasterio 可直接读取转换参数，无需仅依靠旁边的 JSON。独立来源清单包含工程区域、输入 job ID、原始产品 ID、来源链接、校验值、采集时间及输出计划的 calibration。结果不是 COG。

本地单波段检查与缩略图沿用 [反射率读取限制](reflectance-inspection.md)：单文件 512 MiB、单边 20000 像元、完整校验后的显示采样。16 位工程输出的回读也要求单边不超过 20000 像元；较大的范围需要拆分。普通 SCL / RGB 工程处理继续使用已有流式实现，不受旧版 800 万像元总量限制。

## 已验证的范围

[机器验收记录](../prototype/qa/reflectance-processing-verification.json)将真实文件和夹具分开：

- 同一隔离工程中已实际下载的 Landsat 9 红、绿、蓝原始文件分别生成 680 × 596 的工程裁剪结果。Rasterio / GDAL 对原文件窗口和输出的全部 **1,215,840** 个 DN 做独立比较，差异为 **0**。
- CRS、30 米网格、输出边界、NoData、scale / offset、像元中心及 SHA-256 均通过独立核对。原 PixelIsPoint 格网转为 PixelIsArea 后无 15 米偏移。
- 原始 UInt16 和 HLS Int16 的重叠覆盖、NoData、零值、负值、多边形遮罩、错误参数、源哈希变化、取消及重启后缓存复用使用确定性夹具验证。
- UInt16 和 Int16 各 900 万像元夹具跨多个输出条带回读，所有原始 DN 一致。此项是处理器测试，未冒充 NASA 真实账号下载或多景真实 Landsat 下载。
- 实际本地运行时响应驱动浅色 / 深色 1440 像素及浅色 1024 像素的工程、结果检查和地图像元验收；浏览器地图查询再由 Rasterio 核对。只用固定样本重放无关的公开探索目录，文件、栅格和取值均来自真实本地运行时。

NASA / Copernicus 授权入口已在软件设置中。真实账号授权和受保护原产品下载尚未验收；Copernicus SAFE 内的 JP2 解码、显示及处理已通过合成文件验证，完整生产产品待验收，见[SAFE 处理](safe-processing.md)。本轮未生成安装包或公开发布。
