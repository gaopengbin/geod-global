# Agent 图片输入

2026-10-06。软件内 Agent 可以添加图片、点击放大预览、移除草稿图片，以及发送图片消息。发送失败保留草稿；发送成功后，图片留在对话历史里。是否能识图取决于所选模型，保存模型设置不表示该模型已经验收。

桌面端接收明确选择的 PNG、JPEG 或 WebP，每条消息最多 3 张、每张上传不超过 2 MiB。原生解码器核查实际格式，拒绝损坏文件和超过 4096 × 4096 的图像，检查解码内存上限。预览保持方向、按需缩小至最长边 1024 像素，再编码为不带上传附加元数据的 PNG；小图不会放大。用户原文件保持不变。

预览副本以内容哈希保存到应用自己的 Agent 图片目录，重复内容复用同一文件。应用的 `sessions.json` 只保存文件名、尺寸、字节数和哈希引用，不嵌入图片或任意文件路径。Codex 的私有恢复记录仍会保存图片内容，以便模型在后续轮次继续读取。每段对话最多 6 张不同预览、合计 15 MiB；本地图片存储上限 128 MiB。

打开 Agent 的“对话历史”，点击“附件存储”，可查看图片及文本附件的占用和未使用副本，再明确点击清理。原生端在同一状态锁内读取所有模型连接的会话引用，保留对话和当前草稿中的图片，只移除应用目录中的完整、已校验、未引用预览副本。源图片、工作空间文件、对话历史和 Codex 私有恢复记录均保留；未知或损坏文件也不会被当成可清理图片。回复进行中禁止清理；这项管理操作不属于模型工具，也不发起模型调用。

提交只接受已有图片哈希，不接受模型提供的文件路径或远程图片地址。继续对话前重查文件及历史引用；图片缺失或被改动时拒绝继续提交，并保留旧记录。桥接层只接受用户消息里的有限图片数据，保留原来的文字、工具白名单和执行审核边界。图片和图片中的文字是用户数据，不能授权命令、文件读取或计划执行；地理位置、原始像元、来源和任务完成状态仍须依赖真实 GeoD 工具。

图片使用唯一 Codex 编排循环。三种协议的受控上游验证均经过真实 SDK、Codex 与独立原生 GeoD 工程库；桌面原生后端、内部 Node 通信和同线程恢复也单独通过。受控上游和测试图形不作为云端生成或实际 GIS 栅格成果。

上下文整理后，应用会重新附带本段对话已选择的图片；对话中途自动整理时，桥接层也会补回请求中缺失的图片。仍核查原生保存文件和内容哈希，保留工具调用与结果的配对。历史引用的比较按字段值进行，原生 JSON 字段排序变化不会再被误报为图片修改。范围和证据见[上下文整理](agent-context.md)。

真实 GPT 网关路线完成两轮识图及工程查询，重启后继续同一线程：正确描述左侧红色圆形和右侧蓝色方形，且本次原生工程查询均返回 0。该记录只证明这条配置下的图像和工具往返，不核实上游厂商，也不推广为所有模型可用。原生 Claude / Gemini 的真实云端验收仍未通过。

中文深色和英文浅色界面在隐藏浏览器检查历史图片、草稿、放大预览、失败保留、发送清空和移除；它不代替原生窗口或安装环境验收。代码检查、测试、受控与真实调用、最终开发程序身份见[图片验收记录](../prototype/qa/agent-images-verification.json)。
