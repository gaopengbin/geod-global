# Copernicus DEM GLO-30 Public

2026-10-02。桌面探索页已提供独立高程数据入口，共用区域选择、目录分页、工程、原文件下载和任务恢复。下载后可在我的数据查看持久化缩略图，在工作空间显示灰度高程并点击读取原始像元。

该入口使用 Earth Search 的 `cop-dem-glo-30` 目录和 AWS `eu-central-1` 的公开 GLO-30 COG，不需要账号。只转换与选定瓦片完全一致的官方 `s3://copernicus-dem-30m/<cell>/<cell>.tif` 路径；工程和任务保存固定 HTTPS 原文件链接，不接受凭据、查询签名或任意 S3 桶。[公开数据说明](https://registry.opendata.aws/copernicus-dem/)

这是包含建筑和植被的数字表面模型（DSM），采用 2021 公开版本。并非全部陆地区域都有公开瓦片，海洋没有瓦片；空结果不补造高程，也不作为服务故障。目录时间作为参考记录保留，不显示成瓦片的观测日期；该入口没有云量、日期筛选或观测时间轴。

## 原始值与空间网格

原生读取要求完成的 `elevation` 下载、固定产品身份、托管路径、字节数和 SHA-256。解析原文件的单波段 IEEE Float32、EPSG:4326、度制 PixelIsPoint 网格，并核对具名一度瓦片的坐标与间距。高纬度瓦片允许官方公开 COG 的不同列数；不能全部硬编码为 3600 列。[COG 格式说明](https://copernicus-dem-30m.s3.amazonaws.com/readme.html)

PixelIsPoint 的整数经纬度是像元中心，显示范围采用半像元外边界。地图缩放使用角度间距，水平坐标与像元尺寸标为度；原始高程使用米，相对于产品规定的 EGM2008（EPSG:3855）。该垂直基准来自固定产品规格，不把 TIFF 的水平 EPSG 当作高程基准。[产品规格](https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM)

灰度采用全分辨率抽样的 2–98 百分位拉伸，仅影响预览。地图取值读取原始分辨率数据块，Float32 精确提升为 Float64 传输；0、负数与小数均可为有效高程，不套用反射率转换或 DN=0 掩膜。仅按文件 NoData 声明判定缺失值；NaN NoData 在 JSON 中返回 `null` 和明确标志，未声明的 NaN 或无穷值拒绝读取。

缩略图复用现有原生持久化缓存，按任务、源 SHA-256 和生成版本绑定。命中仍校验托管源文件；产品身份和资产类型也在缓存读取前检查，缓存不能掩盖源文件丢失或修改。

## 工程裁剪与拼接

完成原始高程下载后，工程提供单瓦片裁剪及多瓦片拼接裁剪。按原始 Point 网格向外取整，保留单波段 Float32、经纬度角度间距、像元中心、米制高程与 EGM2008 参考；输出 GeoTIFF 写入水平 EPSG:4326、Point 和垂直 EPSG:3855 / 米的 GeoKey，并生成包含原文件 SHA-256、目录参考日期、许可链接和工程区域的侧车元数据。

处理分块解码和写入，逐块回读核对；不把整幅输出塞进内存。不同经度间距的高纬度瓦片拒绝混拼，不自动重采样或重投影。有效的零、负值和小数逐位保留。原文件自身的 NoData 不覆盖有效来源；拼接缺口和多边形外像元写为明确的 NaN NoData。多边形按原始像元中心判断。输出可在工作空间显示、取值，并复用同一持久化缩略图缓存。

## 验收与边界

[实际验收记录](../prototype/qa/dem-native-verification.json)包含一次完整匿名下载（20,060,161 字节）、独立重新计算的 SHA-256、六个与 Rasterio/GDAL 逐值一致的像元（包含负高程、有效零值和小数），以及重启后的缩略图复用。

界面验收在无头浏览器中完成，使用真实目录条目回放、隔离 Rust 运行时和真实下载文件。软件内创建工程并加入下载队列，复用已完成的原文件；1440 浅色、1440 深色和 1024 浅色覆盖搜索筛选、下载、工程、检查和地图取值。浏览器测试桥单独允许本机 HTTP，生产桌面 CSP 未放宽。原生单元测试另外覆盖高纬度网格、NaN NoData、错误 CRS / PixelIsPoint / 具名瓦片、非法地址和篡改文件。

两块真实公开瓦片（20,060,161 与 47,669,564 字节）经原生下载与 SHA-256 核对，在界面中分别执行单瓦片工程裁剪和两瓦片拼接裁剪。Rasterio/GDAL、tifffile 与 NumPy 独立检查两个新 GeoTIFF 的 Point 网格、Float32、垂直 GeoKey、NaN NoData，以及全部 686,630 个输出像元；有效样本的 IEEE Float32 位与对应原文件完全一致。真实派生结果重启后的缩略图、元数据和像元值保持一致；派生文件在 1440 明暗与 1024 浅色界面检查通过。高纬度多边形掩膜、原始 NaN 和错误网格另外经合成夹具测试，不冒充额外实际下载。空目录、目录 HTTP 503、检查加载 / 失败使用受控状态夹具；重试恢复读取真实文件。

目前支持原始瓦片下载、显示、取值及同网格工程拼接裁剪。**重投影、坡度 / 山体阴影分析尚未接入**。GLO-90 和 SRTM 使用独立入口，分别见[GLO-90 验收](glo90-inspection.md)与[SRTM 说明](srtm-inspection.md)，不能互换分辨率、垂直基准或文件类型。
