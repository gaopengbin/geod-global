# WMTS 地图影像

2026-10-02。**我的数据 → 地图影像 → 获取地图影像** 现可选择公开 WMTS 1.0.0 服务。软件界面、桌面原生核心和 CLI 共用连接、取图、保存及导出流程；已保存的 WMS 影像继续使用原有入口。

选择 WMTS，填写服务名称和不带查询参数的 HTTPS 地址，再连接服务。2026-10-03 增加服务接口（KVP）/ 能力文件（XML）地址类型，以及服务声明的 REST ResourceURL；“填入 NASA GIBS”随地址类型提供示例，详见 [REST 接入与最新验收](wmts-rest-map-images.md)。连接后搜索图层，选择服务日期、样式、瓦片网格和层级，按当前探索区域保存影像。界面显示所选层级对应的实际输出宽高；超出当前面积或瓦片数量限制时，需要缩小区域或选择较粗层级。请求使用设置中的系统、直连或自定义代理。

## 图像、网格与来源

当前支持声明为 EPSG:4326 / CRS:84 或 EPSG:3857 的网格，以及 PNG、JPEG 瓦片。连接读取服务的矩阵标识、比例尺分母、左上角、单瓦片宽高、矩阵行列数和图层瓦片限制。EPSG:4326 的纬度 / 经度轴序按声明解析；CRS:84 使用经度 / 纬度轴序。层级标识按服务原文使用，不把它当成 XYZ 缩放级别，也不假设瓦片固定为 256 像素。[WMTS 标准与字段定义](https://schemas.opengis.net/wmts/1.0/wmtsGetCapabilities_response.xsd)

请求区域以 WGS84 经纬度记录，输出向外对齐到所选矩阵的整像元边界。程序从原始瓦片复制对应像元窗口，保留原生网格，不对保存结果重采样；多个覆盖限制矩形之间的空缺也不会被合并成可下载范围。来源同时保存用户请求范围、实际地理范围、原生 CRS 范围和像元窗口。选择多边形时保存其几何，当前输出仍为外接矩形，不执行多边形遮罩。

PNG 展开为 RGBA，JPEG 解码为 RGB 并补充不透明 alpha；地图预览与导出读取同一份保存影像和坐标。瓦片中的颜色是服务渲染结果，不能用于替代原始反射率、温度、气溶胶数值或其他科学波段。服务日期表示请求的可视化时间，也不自动成为单景拍摄时间。NASA GIBS 提供多种渲染产品，实际产品含义应以图层说明为准。[NASA GIBS 服务说明](https://nasa-gibs.github.io/gibs-api-docs/access-basics/)

影像及原始瓦片归档保存在独立应用数据目录。来源包含服务、图层、样式、日期、Capabilities SHA-256、矩阵参数、每块瓦片的行列号 / 请求地址 / 字节数 / SHA-256，以及归档和组装影像的 SHA-256。打开影像时校验本地 PNG，导出时另外检查原瓦片归档；界面不需要重新向服务取图。地图沿用本地参考底图、可调整宽度的信息面板、完整高度缩略图和来源弹窗。

## 导出内容

桌面通过保存对话框、CLI 通过明确目标路径导出 ZIP，不覆盖已有文件。包中包含：

- `map.png`：按声明网格组装的 RGBA 影像。
- `map.pgw`：原生 CRS 下的像元中心坐标和间距。
- `map.png.aux.xml`：GDAL 可读取的 CRS、轴映射和像元角点变换。
- `source-tiles.zip`：服务实际返回的 PNG / JPEG 原样字节，以行列号命名。
- `source.json`、说明文件和逐文件 `checksums.sha256`。

经纬度与 Web Mercator 使用各自原生单位；不会把 Web Mercator 的米坐标标成经纬度。导出包不包含绝对本机路径，但仍包含所选区域、服务地址和查询来源。服务声明的使用限制为空或 `none`，不表示软件为所有来源授予再利用许可；具体数据仍按供应商要求使用。

## 2026-10-02 KVP 实际公开数据验收

使用隔离的实际原生运行时访问 NASA GIBS 两个 KVP 端点：

- `https://gibs.earthdata.nasa.gov/wmts/epsg4326/best/wmts.cgi`
- `https://gibs.earthdata.nasa.gov/wmts/epsg3857/best/wmts.cgi`

日期均为 `2025-06-27`，请求范围为 `[-125,30,-110,43]`。本次实际取得的三份输出如下：

| 图层 | 输出 CRS / 原瓦片格式 | 输出尺寸 | 原瓦片数 | 独立像元核对 |
|---|---|---|---|---|
| `MODIS_Terra_CorrectedReflectance_TrueColor` | EPSG:4326 / JPEG | 855 × 741 | 4 | RGB 解码最大差 4 个色阶，平均差约 0.143；alpha 完全一致 |
| `MODIS_Terra_CorrectedReflectance_TrueColor` | EPSG:3857 / JPEG | 683 × 740 | 16 | RGB 解码最大差 4 个色阶，平均差约 0.133；alpha 完全一致 |
| `MODIS_Terra_Aerosol` | EPSG:4326 / PNG | 855 × 741 | 4 | 全部 2,534,220 个 RGBA 通道值完全一致 |

24 块原瓦片均重新通过独立 HTTP 请求取得，与导出归档中的原始字节逐块一致。JPEG 的色阶差来自两个独立解码器，并非原文件差异；原始 JPEG 字节与 SHA-256 完全一致。Pillow 独立解码和组装参考窗口；GDAL / Rasterio 独立核对三份导出的 CRS、尺寸、范围、像元变换及全部输出通道。归档中的影像、来源记录和逐文件校验值均通过检查。该过程使用真实公开响应，没有以夹具或缩略图替代瓦片。

本次经纬度服务发现 1196 个兼容图层，Web Mercator 服务发现 1187 个。Web Mercator 的 9 个图层声明了越出矩阵范围的瓦片限制，相关无效网格已排除并在“服务兼容性说明”中保留名称和原因；其他有效图层仍可使用。图层数量是当次能力发现结果，不代表这些图层都已逐项取图验收。

界面验收使用无头 Chromium、实际原生服务和真实 NASA 请求，覆盖 1440 像素英文浅色界面、1024 像素中文深色界面，两种投影的日历 / 网格选择、实际取图、等高卡片、来源弹窗、导出字节与地理地图显示；页面未报告脚本错误。过程中未操作用户桌面，**未声称已完成安装版 WebView 或本机保存对话框人工验收**。

停止服务后，以更新后的原生程序分别打开两个独占存储：6 张 WMTS 影像和此前保存的 6 张 WMS 影像均恢复成功。每张影像的元数据、PNG 字节及导出校验值一致，WMTS 原瓦片归档也逐项核对一致。复验仅调用本地列举、检查及导出，不重新连接远程服务。

回归通过 223 项原生核心测试、3 项 CLI 测试、4 项桌面测试、141 项前端逻辑测试和 134 项界面测试，另有 4 项需显式启用的原生测试未运行。依赖隔离、接口契约、方案结构、前端构建及严格 Clippy 检查通过。复验脚本：[verify-wmts-public.py](../scripts/verify-wmts-public.py)；具体数据与验收边界见[验收记录](../prototype/qa/wmts-public-verification.json)。

## 当前限制与剩余接入

服务必须为公开 HTTPS、443 端口，并声明兼容的 HTTP KVP GetTile 或 REST ResourceURL。请求不跟随重定向，不携带 URL 凭据或任意查询参数，WMTS 取图端点限定在已连接服务的同源路径；WMS 原有目录限制保持不变。XML 最大 8 MiB；不读取外部 DTD、不接受实体声明。每个连接最多 128 个矩阵集、每组 64 个层级，WMS / WMTS 共用最多 24 个连接和 512 张影像的登记上限。

一次取图最多 16 块瓦片、输出每边最多 2048 像素；单瓦片不超过 4 MiB、原瓦片归档不超过 64 MiB，组装 PNG 不超过 16 MiB。取图有 120 秒总超时，不是持久下载任务。支持明确日期 / RFC3339 时间和已支持的简单周期；不隐式改用 `current` 或最近日期。当前不接受 16 位或动画 PNG，也不自动填充其他额外维度。

后续仍需接入认证与内网服务、其他投影和维度、大范围任务队列 / 取消 / 断点续取、GetFeatureInfo、多图层组合、精确多边形处理以及工程内混合数据流程。WCS、自定义 STAC / COG、Wayback、其他瓦片与商业服务也仍按[完整接入状态](provider-integration-status.md)推进；公开 WMTS 渲染影像可用不等于全部数据源或科学原产品接入完成。

## CLI 请求

复用 `map-services` 和 `map-images` 命令，调用方式见 [WMS CLI](wms-map-images.md#cli)。连接请求增加明确的协议：

```json
{
  "name": "NASA GIBS",
  "url": "https://gibs.earthdata.nasa.gov/wmts/epsg4326/best/wmts.cgi",
  "protocol": "WMTS"
}
```

取图请求使用连接返回的 `serviceId`，并填写该图层实际声明的 `tileMatrixSet`、`tileMatrix`、样式与时间。`bounds` 仍为 WGS84；`width` / `height` 必须与范围在所选网格中的整像元窗口一致，不能另设缩放尺寸。界面会计算这些值；CLI 可按服务返回的矩阵参数计算，实际复验脚本提供了示例。HTTP 接口不接受本机任意导出路径。
