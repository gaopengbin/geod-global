# GeoD Global — 决策、契约与发布门禁

**日期：2026-09-21 · 状态：契约与商业方案 proposed；独立仓库决定 confirmed · 本文件是 00–04 的执行补充，不是已实现 API 或已批准的商业方案。**

本轮把完整终态转为可以逐项实施的工程约束。代码现状及复用位置以 [05-Code-Baseline-and-Implementation-Map.md](05-Code-Baseline-and-Implementation-Map.md) 为准；00–04 继续保留产品范围、研究与推广材料。本文件没有重新核验外部政策、进行用户访谈、申请商户、发送外联或启用收费。

## 1. 谁决定了什么

不得因为同一建议在聊天、总纲、文案里出现多次，就把它升级为用户决定。

| 类别 | 内容 | 本轮处理 |
|---|---|---|
| 用户明确要求 | 专门做符合国外审美与需求的版本 | 保留独立海外体验；英文界面不能作为完成标准 |
| 用户明确要求 | “不要首版，要设计就要完整的” | 全量页面、六个数据域、可靠性、商业与运营均保留；阶段只表达依赖 |
| 用户明确要求 | 海外需求、海外推广、海外支付都要考虑 | 研究、渠道和交易闭环进入工作包，不能推到产品做完后再想 |
| 用户明确要求 | “是一个新仓库吧，不和现有的国内版混在一起吧？”并确认“可以，开始吧” | Global独立目录/仓库、依赖/配置/构建/发布；不迁移国内工作树；替代同一主干建议，见08 |
| 当前行动授权 | 开始落实独立仓库与隔离 | 执行本地建仓和解除原型外部依赖；授权不等于已批准所有技术或商业方案 |
| 既有设计方向 | 本地优先、可选 AI、无 GeoD 账号也能开始本地工作；未来可复用版本化核心库 | 用作可逆工程设计基线；跨产品复用不得绑定两个工作树或发布节奏 |
| 待技术验证 | OpenLayers、Viewer adapter 的具体实现 | 与当前引擎同条件测试后形成 ADR；不得把 OL 写成已选型或当前依赖 |
| 设计基线与后续验证 | 用户反馈原型“看起来不错”；现有地图/面板/时间轴结构作为后续基线 | 保留已认可的原型方向；完整可访问性、真实任务可用性与各平台WebView仍需验证 |
| 待商业决策 | 桌面 Pro、Cloud、Teams、专业服务及组合 | 作为并列候选评估，不直接建收费墙 |
| 待定价决策 | 原文 $99/$399 等数字 | 内部实验假设；不能进入可购买正式价格 |
| 待经营验证 | 支付渠道、经营主体、银行、币种、到账 | 只记录待核验项；原文候选不等于批准、资格或当前政策 |

**文档冲突解释**：01 开头的商业一句话及第19–23节描述的是 Cloud/服务方向提案；03 中对应文案是条件模板。它们不能覆盖本表的“待商业决策”状态。已有代码/许可证事实也不能直接推导未来全部新功能必须采用同一种收费方式。

仓库决策以[附件08](08-Repository-Boundary.md)为准。本文中的“共享契约/同一Job”默认指 Global 自己的桌面、CLI、MCP；跨国内/海外产品的共享只能通过明确版本的库。附件05中的国内源码位置是历史只读参考，不能作为本仓编译或运行路径。

决策记录采用：`id / question / options / evidenceRefs / chosenOption / decisionOwner / decidedAt / reversible / consequences / reviewTrigger`。未决定时 `chosenOption` 和 `decidedAt` 均为 `null`，不能用默认选中或方案排序暗示批准。

## 2. 商业决策表：先验证价值，再选择包装

以下是产品比较，不提供新的支付政策、税务或法律结论。

| 方案 | 付费对象与新增价值假设 | 必须获得的证据 | 工程与运营代价 | 否定/调整条件 |
|---|---|---|---|---|
| 桌面 Pro / 独立商业组件 | 有重复本地任务、需要专门新能力或维护保障的个人/团队 | 具体新功能边界、现有权利与贡献清单、真实预算、离线/更新期偏好 | 权益缓存、离线使用、版本更新边界、恢复购买、长周期兼容 | 只是把现有免费 CLI/批量重新加锁；用户不愿为新增能力支付 |
| Cloud Workspace / Teams | 多人共享配方、审计、通知、运行管理 | 用户允许上传哪些元数据；现有 JSON/Git 无法解决的成本；采购者预算 | 账号、租户隔离、备份恢复、删除导出、值守、持续成本 | 用户只需要本地文件；不允许工作区范围出网；协作价值不足 |
| 专业服务 / 维护合同 | 数据源接入、部署、工作流培训或明确交付 | 有边界的任务、样例输入/输出、验收人、可承担报价和工时 | 报价、交付验收、支持记录、容量安排；服务收入与软件收入分别记录 | 每单高度定制且无法覆盖工时；合同承诺超出实际能力 |
| 混合方案 | 上述不同用户分别购买所需价值 | 至少一个单项价值已验证，权益和商品解释不混乱 | 多商品账本、支持分流、更复杂文案与定价 | 组合仅为了“什么都卖”；尚无任何单项需求证据 |

下一项商业交付是 **一张权益边界表 + 三份真实任务研究记录 + 成本估算模板**。权益表逐项记录 `现有能力 / 拟新增能力 / 本地或云 / 权利状态 / 收费候选 / 证据 / 决定人`。在选择前，允许开发与商业模式无关的契约、成果验证、独立产品壳和原型。

需求证据档案保持四种状态：`planned → collected → analyzed → decision-ready`；“计划访谈18人”仍为 planned。三份任务不是三个虚构用户故事，每份必须有实际受访者许可的去敏输入、目标成果、当前工具和失败成本。未经单独授权，本轮不发送邀约。

## 3. 完整范围的实施依赖

### 3.1 修正 F02 的循环解释

02 的总图把 F02 放在处理器前，表格却把 F02 依赖写成 X01–03。将原工作包拆为两个子项，保留原编号追溯：

- **WP-F02a 验证协议和框架**：依赖 A01/F01。交付验证器注册、报告结构、必需输出声明、错误分类、提交门槛；先于具体处理器。
- **WP-F02b 格式与数值验证器**：每一种随对应处理器交付。例如 raster 依赖 X01，vector 依赖 X02，3D 依赖 X03；不要求等待所有处理器完成。
- 处理器可以先产生临时结果；仅当对应 F02b 验证通过，F01 才把该结果提交为有效 Artifact。
- F03 依赖 F01 和 F02a；可展示“待验证”结果，但不能将其计入有效成果。没有 X03 不阻塞已验证栅格成果入库。

```text
A01 契约 ── A03 凭据/策略 ── P01 Provider SDK ── P02/03/04/05 各来源
  ├── J01 状态引擎 ── J02 持久化/恢复
  ├── F01 成果模型 ── F02a 验证协议 ── F03 成果库
  ├── V01 Viewer adapter ── V02 栅格 ── 对应显示验收
  └── V03 3D Viewer

X01 栅格 ── F02b-raster ── 已验证栅格交付
X02 高程/矢量 ── F02b-elevation/vector ── 已验证高程/矢量交付
X03 3D打包 ── F02b-3d ── 已验证3D交付
各 X 工作包同时依赖 A01、J01、F01/F02a 和实际所需 Provider/运行时

A01/J01 ── W01 Recipe 预检与固定输入 ── W02 CLI ── W03 MCP
已验收处理器逐个注册到 Recipe；不等待六域全部实现才定义 Recipe
```

## 4. 契约结构与边界

随附 [draft-contract.schema.json](contracts/draft-contract.schema.json)、[examples.json](contracts/examples.json) 与 [verify_contracts.py](contracts/verify_contracts.py)。版本固定为 `0.1.0-proposed.1`；它们定义设计样例，不是当前 Rust/Tauri/CLI 接口。样例中的 Provider、来源、校验和、文件路径和 Job 均为明确的虚构 fixture，没有真实下载成果。

### 4.1 七个对象的最小字段

| 对象 | 必需语义 | 额外检查 |
|---|---|---|
| Area | `id, name, geometry, originalCrs`；geometry 固定 GeoJSON WGS84经纬度 Polygon/MultiPolygon | 保留洞与多区；ring闭合、经纬度范围、拓扑有效性；跨日期变更线显式分区；本地原坐标另存，不能混入 WGS84 |
| Dataset | `id, providerId, collectionId, dataDomain, title, capabilities, policyRef` | dataDomain 使用 satellite/imagery/elevation/vector/3d/local；能力和授权分别判断 |
| Item | `id, datasetId, providerItemId, observedAt或observedInterval, publishedAt, footprint, assets, revision` | 观测未知允许显式null，不用发布时间替代；asset持久化逻辑ID、版本/etag，临时签名URL运行时解析 |
| Layer | `id, sourceRef, visible, opacity, order, displayStyle` | sourceRef指Item/Artifact；显示style不覆盖分析值，显示表达式与输出算子分别存放 |
| Recipe | `id, version, areaId, inputs, outputPolicy, outputs, resourceBudget` | 固定输入与动态查询分开；操作图只引用注册算子；凭据只允许本地绑定引用，导出移除 |
| Job | `id, recipeId, attempt, state, outputPolicy, outputs, artifactIds, createdAt, updatedAt` | 运行时冻结配方及输入快照哈希、策略版本；提交前校验；预期输出与结果逐项对照 |
| Artifact | `id, jobId, outputId, files, provenance, validation, committedAt` | 相对文件路径与输出根分开；字节数、SHA256、格式、来源、引擎版本和校验报告；文件必须真实存在后才能valid |

本轮机器契约实现 Area/Recipe/Job/Artifact 的结构与结果归约样例；Dataset/Item/Layer 的最终 schema、算子图和完整空间拓扑检查是 CT-02/CT-03 明确交付，不能因表格存在就视为已经实现。Recipe 的少量输入字段只演示固定资产引用；Dataset/Item/Layer 落地后迁移到稳定引用。

### 4.2 错误与进度

统一错误形状：`code / message / retryable / detailRef`，按需要加 `outputId / providerId / retryAfterSeconds`。message供用户阅读，程序只判断稳定code；detailRef指向脱敏日志，不能包含令牌或签名URL。

| code | 语义与动作 |
|---|---|
| `NO_COVERAGE` | 当前查询无匹配；更改区域/时间，不反复网络重试 |
| `AUTH_REQUIRED` / `AUTH_EXPIRED` | 等待该来源认证；不误导成GeoD订阅不足 |
| `POLICY_DENIED` / `POLICY_UNKNOWN` | 当前操作禁止或证据不足；审批按钮不能改写禁止策略 |
| `CAPABILITY_UNAVAILABLE` | 当前构建/运行时无法执行；返回缺失组件 |
| `RATE_LIMITED` / `NETWORK_ERROR` | 按来源重试规则与次数上限处理 |
| `DISK_FULL` / `OUTPUT_CONFLICT` | 暂停在安全边界；原文件和已提交成果保持原样 |
| `VALIDATION_FAILED` | 结果不可交付；保存报告与临时产物，不能计成功 |
| `SCHEMA_UNSUPPORTED` / `INPUT_CHANGED` | 版本或冻结输入变化，重新预检；不得静默代替数据 |

进度使用 `phase / completedUnits / totalUnits|null / unit`。total未知时显示活动状态；阶段完成不等于Job成功，下载100%后仍可能校验失败。进度与错误不是本轮draft schema全部覆盖的字段；生产契约必须在CT-03补齐后才能对外承诺稳定。

## 5. 状态迁移、Partial与恢复

### 5.1 执行状态

| 从 | 到 | 条件 |
|---|---|---|
| Draft | Validating / Cancelled | 冻结输入开始预检；或尚未执行时取消 |
| Validating | Queued | 参数、能力、授权、磁盘预估通过；无新的必要用户决策 |
| Validating | AwaitingApproval | 具体成本/外传/覆盖尚未获授权，并附可审阅计划哈希 |
| Validating | Failed / Cancelled | 无法执行或用户取消；错误必须可定位 |
| AwaitingApproval | Validating / Cancelled | 用户决定后重验计划；批准绑定哈希，计划变化必须使旧批准失效 |
| Queued | Running / Cancelled | 工作器取得互斥执行权；开始前重验易变授权/资产 |
| Running | Paused | 仅可安全检查点暂停；认证/空间等待记录reason |
| Paused | Validating / Cancelled | 恢复前核验输入、策略、文件和检查点；或取消 |
| Running | Succeeded / Partial / Failed / Cancelled | 输出已清点、验证、提交或隔离；状态与成果一致 |

`Succeeded/Partial/Failed/Cancelled`为不可回写的历史终态。重试新建Job ID，保存`retryOf`及递增attempt；不把旧失败改成成功覆盖审计。批次重试允许引用旧的有效Artifact，但必须重新核验引用和校验和，不能无条件复用。

恢复状态作为独立字段 `recoveryState = none / scanning / resumable / needs_review / unrecoverable`，不是让任务凭空从Running跳回Draft。进程崩溃后停止调度，扫描已持久化日志和临时区；具备检查点的任务进入Paused并标resumable，没有足够证据的标needs_review，不自动重复有外部副作用的操作。恢复失败可以终结为Failed，保留原日志。

### 5.2 单任务与组合任务的结果归约

Recipe在执行前冻结 `outputPolicy = all_required / best_effort`，每个预期输出含`required`。每个输出最终为`valid / failed / skipped`，必须有稳定ID；`valid`必须引用通过验证且已提交的Artifact。没有预期输出的计划在预检阶段拒绝。

| 条件 | 最终状态 |
|---|---|
| 所有声明输出都valid | Succeeded |
| `all_required`，至少一个required输出不valid | Failed；仍允许用户找到其他已验证成果 |
| `all_required`，全部required有效，但存在可选输出failed/skipped | Partial |
| `best_effort`，至少一个输出valid且至少一个未交付 | Partial |
| 任一策略下没有valid输出 | Failed |
| 用户明确取消且取消已生效 | Cancelled；保留有效成果清单与取消原因 |

`best_effort`用于显式允许独立交付的组合计划，例如影像完成但DEM来源失败；不能把3D包缺少必需纹理、同一栅格缺少必需波段、校验失败的文件当作有效输出。一个“输出单元”必须能独立打开和使用。组合任务的required仍表示用户意图，best_effort只允许部分交付，不把缺失required改为Succeeded。

即使已经全部写完，只要用户取消先被引擎接受，按Cancelled记录；终态持久化之后的迟到取消返回`ALREADY_TERMINAL`，不改终态。`NO_COVERAGE`可在组合计划中成为skipped并附原因，不能偷偷删去该预期项后声称全部成功。

### 5.3 事件与一致性

每个Job事件包含`jobId / attempt / sequence / eventId / occurredAt / type / payload`。同一attempt的sequence单调增加，去重以eventId为准；客户端忽略已处理事件，发现序列缺口拉取权威快照。引擎使用比较版本写入终态，防止取消、完成、重试竞争。最后一个检查点与文件提交记录先持久化，再发布“已完成”事件。

## 6. Schema版本与兼容

1. 当前`0.1.0-proposed.1`仅允许精确版本，导入别的版本返回`SCHEMA_UNSUPPORTED`。生产契约冻结前不承诺向后兼容。
2. 产品版本、文件schemaVersion、Provider版本和引擎版本分别记录；软件更新不自动重写用户文件。
3. 1.0以后，新增可忽略的可选字段才允许minor；必需字段、类型、单位、枚举意义或状态语义变化升级major。声明允许扩展不代表可忽略影响执行的字段。
4. 本轮schema使用严格字段白名单。未来读者只接受其声明支持的版本，先用该版本schema验证，再进入明确迁移器；不得因为是同一major就绕过白名单。
5. 迁移为纯函数：`old → new + migrationReport`；原文件保留，输出新路径，附原文件SHA256、迁移器版本和警告。迁移失败不产生半写文件。
6. 有损迁移、未知操作、未知单位、无法恢复许可依据时停止执行并给出具体差异。禁止把未知算子当no-op。
7. CI保存每个受支持版本的golden fixtures；校验当前、迁移旧版本、拒绝未来版本、无秘密导出。弃用必须有可导出和读取窗口，不能静默删除旧配方。
