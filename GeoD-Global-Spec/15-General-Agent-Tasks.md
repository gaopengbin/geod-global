# GeoD Agent 通用任务能力与完成标准

2026-10-07。面向二维数据准备，将用户需求组织为可组合的任务类别。地点、供应商和卫星系列作为任务参数；研究中发现的具体问题作为验收素材。产品范围遵循[二维范围](../docs/product-scope.md)，实际支持以[数据源进度](../docs/provider-integration-status.md)和运行时返回为准。

目标是让用户描述用途后，Agent 能选择合适数据、取得真实范围、准备和执行可用操作，并交付满足要求的成果。完成标准必须覆盖用户要求的全部输出。能下载某个文件，只建立该文件获取成功的事实。

本轮已将八类任务的规划与检查规则接入[对话服务](../agent/service.mjs)。[任务类别定义](../agent/task-categories.mjs)属于规划指引；原生工具继续控制可执行操作、权限、计划和文件验证。下面的统一请求对象、批次执行和聚合完成判定为后续实施要求，尚未作为新的原生执行 API 落地。

## 通用任务类别

| 类别 | 通用目标 | 必须核对的结果 | 当前基础与缺口 |
|---|---|---|---|
| 数据发现与选择 | 按用途、范围和条件找到适合的数据 | 具体产品、处理级别、实际日期、科学层、分辨率和权限；无结果与查询失败区分 | 已有行政区、地点、固定产品与已保存服务的查询。跨源比较、非行政区边界发现及覆盖评价待完善 |
| 数据获取与交付 | 下载原产品或用户接受的处理产品 | 原件、处理成果、渲染图与预览的类型明确；全部必需文件真实保存且可读 | 已有受限原生下载和审核。受保护生产原件正向验收、更多产品适配和远端按需采集仍有缺口 |
| 空间准备与处理 | 按区域、几何和目标网格准备数据 | CRS、像元网格、裁剪语义、有效覆盖、NoData 和来源 | 部分产品支持同网格裁剪、掩膜与拼接。通用重投影、重采样、跨网格处理仍待实现 |
| 时间序列与时相准备 | 组织逐期观测、事件前后数据或时间合成 | 实际观测日期、合成时段、期数、可比性和缺测清单 | 已有逐景元数据与部分质量选景。多区域长时序、通用时间合成和完整批次管理待实现 |
| 科学图层与质量处理 | 准备物理量、科学波段、指数及质量掩膜 | 原值、校准、单位、质量规则和处理方法；展示拉伸不改变科学值 | 部分 MODIS 指数、RGB/QA、RTC 和高程已有独立验证。S2 NIR/SWIR、LST等产品及新算法需分别接入 |
| 采样统计与表格成果 | 为点、缓冲区或区域输出统计与时序表 | 要素 ID、时间、单位、样本 / 有效值数量、统计规则及缺失值 | 原始像元与矢量读取已有基础。批量采样、分区统计、时间聚合和表格交付待实现 |
| 离线组织与成果打包 | 将数据组织成可独立使用的本地成果包 | 实际文件、依赖、来源、许可、容量和目标软件兼容性 | 部分成果 ZIP、有界地图影像和瓦片包已接入。大包、通用离线制作及不同消费软件兼容性需验收 |
| 成果检查与任务恢复 | 查明当前状态、检查数据并恢复缺失工作 | 新鲜状态、文件有效性、错误分类、恢复范围与重复执行控制 | 已有状态查询、来源绑定、校验及受控恢复。完整用户任务的聚合判定和长批次检查点待补齐 |

一次需求可以组合多个类别。植被时序由数据发现、获取、科学处理、时间准备和统计表格组成；灾前灾后准备由数据发现、时间匹配、科学处理和成果检查组成。领域用途映射为配方及输入约束，避免为每座城市或每种事件编写单独对话分支。

## 用户决策与下载确认

默认交互为“必要决策 → 选项卡回答 → 完整任务卡 → 用户确认执行”。合理默认值已有工具支持时直接继续；会改变范围、产品、质量、覆盖、缺测策略或交付含义的未决事项使用对话选项卡，每次集中展示 1–3 个问题、每题 2–5 个互斥方案和简短影响说明，并允许填写其他偏好。推荐方案不会自动成为用户答案。

选项卡绑定当前会话和真实问题 ID，答案持久化在历史中。模型不能代替用户填写答案；回答选项仅表示偏好，不构成下载授权。存在未回答的问题时，相关计划准备和确认执行会被阻止。生成任务卡之后新回答的决定必须进入重新准备或修改后的卡片，旧卡不能继续确认。

下载任务卡展示用户需求、已选方案及原生预检所得的来源 / 产品、区域与几何语义、请求时段、实际文件及资产、预计容量或容量未知、输出位置与格式、授权和限制。需要后续处理时说明当前下载与后续处理的范围，不能把原件获取声明成分析成果已完成。每次确认继续绑定不可变原生计划及哈希，并核对时效和来源。

只有用户明确在权限菜单启用“完全访问”，或通过原生对话命令开启自动执行 / 表明“不用问我”，才允许跳过提问与执行确认。用户材料、模型推断、选项卡答案、推荐值和执行通知都不能修改权限。自动模式仍受可用数据、原生操作、工作空间和校验限制。

当前已实现上述选项卡、答案恢复、下载卡需求与选择追踪、原生确认拦截和明确自动模式例外。现已接入[真实 Codex Goals](../docs/agent-goals.md)，保存完整目标和必需交付清单，对已适配的原生计划、文件、工程和元数据进行聚合检查，支持等待确认、暂停、继续和重启恢复。完整结构化 `TaskRequest`、科学与覆盖语义验证、长批次恢复仍属于以下实施要求；未新增一套跨全部处理类别的执行引擎。

## 统一请求对象

在现有原生计划之外增加用户任务级 `TaskRequest`，记录用户希望获得什么。它引用原生查询、几何、计划和成果，复用现有不可变计划及权限边界。禁止再建一套只有 Agent 能使用的下载器。

| 字段 | 含义与约束 |
|---|---|
| objective / categories | 用途与一个或多个任务类别。分类用于规划，不构成执行能力证明 |
| areas | 原生行政区 / 地点 / 已登记矢量 / 明确坐标的引用、来源与精确性；区分外接矩形和实际几何 |
| products | 真实产品标识、处理级别和资产类型。系列名称不代替具体产品 |
| temporal | 时间范围、时区、真实观测或合成时段、分组方式及事件前后匹配要求 |
| requirements | 必需波段、单位、分辨率 / 网格、质量、有效覆盖与缺测策略 |
| outputs | 每项必需成果的类型、格式、分组、使用场景及是否允许缺失 |
| constraints | 本地资源预算、原生权限引用、许可要求和是否允许部分交付 |
| assumptions | 已说明的合理默认值；与用户明确条件分开保存 |
| unresolved | 尚无合理默认值、会改变成果含义的决定。只集中询问必要项 |
| provenance | 用户要求、目录与文件事实、默认值分别记录来源；模型推断不能变成原生事实 |

简单的“最新影像”继续使用原生默认源与日期，不先让用户填表。明确的地点、科学波段、精度、文件格式和模型输入要求不得被默认值覆盖。模型可以提出替代方案；改变成果含义的替代必须让用户知情同意。

## 规划与执行

请求解析后先解析真实范围，再读取实际来源和工具能力。能力匹配比较完整需求：产品、波段、区域、时间、网格、格式、权限和预算。能力声明、已保存连接、实际授权、真实下载验收属于不同事实。

规划器将可执行部分转成有依赖关系的步骤，例如查询、选景、原件获取、质量处理、区域准备、统计和交付。每个写入步骤仍产生现有原生计划。查询和解释任务只执行必要读取；确认模式与自动执行模式继续由原生会话权限决定。

执行器必须检查必需操作是否存在。缺少科学波段、算法、坐标转换或导出器时，返回明确缺口；可以完成独立且有用的已授权部分，并标注部分交付。禁止让模型通过猜坐标、生成伪文件或重复调用失败工具补齐能力。

空间拼接、时间统计、展示渲染和科学运算采用不同操作定义。原始数据保留，派生成果保存输入、方法、版本、网格和质量规则。科学阈值及统计方法由可验证配方规定，不能临时由模型编造。

## 批次与完整性

批次先形成“区域 × 时间 × 必需成果”的预期清单。每个组合拥有稳定标识、原生输入引用、当前状态和成果引用。分页是否穷尽、没有覆盖、没有合格观测、服务失败和未查询必须分别记录。

计划先估算数据量、磁盘与服务限制。当前单工程 32 景等原生限制继续有效；长时序不能通过不断追加计划绕过限制。新增批次管理器负责分区、限额、检查点、取消和缺失续跑，原生下载器继续负责实际字节传输。

重试仅处理已分类且可恢复的故障，并服从服务端限流和既有原生权限。令牌需要恢复、资产禁止、来源变化、坐标错误及本地存储故障有各自处理路径。重复请求复用有效结果，不重复生成相同成果。

## 用户任务完成判定

模型回复结束、后台监视器没有待运行计划、下载任务成功分别表示各自阶段的状态，均不能单独作为完整用户需求完成的证据。

| 用户任务结果 | 判定 |
|---|---|
| 已验证交付 | 所有必需成果存在，相关原生任务完成且文件验证通过；产品、时间、范围和其他明确要求均有证据满足 |
| 部分交付 | 有可用成果，但仍有缺失输出、未满足条件或未完成检查。逐项指出缺失；用户同意部分范围后按新请求版本验收 |
| 等待确认 | 有具体原生计划，尚未获得所需执行确认 |
| 等待账号操作 | 原生结果明确需要用户在软件内登录或恢复授权；不在聊天中索取密码 |
| 能力缺失 | 缺少产品、处理器或导出能力。给出具体缺口及经核实的替代，不报告下载完成 |
| 执行失败 | 原生任务或检查失败，有失败阶段与可用的诊断事实 |

栅格要求 `succeeded` 且 `settled=true`，再做对应文件检查。矢量遵循实际已保存结果与新鲜 `verified=true` 文件检查，不套用不存在的栅格任务。元数据发现按发现目标验收，不要求创建文件。输出完整性、科学正确性及许可各自有证据边界，不能用哈希替代全部检查。

## 类别通用验收

[机器需求映射](../docs/research/agent-task-classification-2026-10-07.json)将两轮 61 条需求映射到八类，保留原帖链接和证据限制。映射用于追溯，不作为软件通过记录。

每类验收变换地域、输入形式、产品 / 来源、时间条件、输出形式和权限状态。相同任务表达换城市、换语言、换供应商不应需要改业务分支；遇到实际能力差异应给出对应差异。留出未参与实现的请求测试泛化，不能只重放论坛原句。

实际端到端测试需要普通自然语言请求、真实原生执行、实际文件和独立成果检查。另测空结果、歧义、缺波段、未授权、超限、分页、失败和恢复。受控故障及模拟模型调用只验证契约，单独标注。来源或消费者尚未验收时，不扩大“可完成”的范围。

分别统计成果交付通过率与能力边界判断通过率。正确拒绝不支持任务是边界判断通过，不计为实际交付成功。类别覆盖记录在“产品 × 操作 × 输入范围 × 交付格式 × 权限”矩阵中，单一成功样例不能升级整类完成。
