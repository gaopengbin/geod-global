# Agent 入口与任务闭环

GeoD Global 有两种 Agent 使用场景，共用原生执行引擎与账号模型连接；入口语义、草稿和默认会话分别管理。

| 入口 | 默认对象 | 不自动带入的对象 | 完成后的去向 |
| --- | --- | --- | --- |
| 会话页 | 用户描述、该会话目标、已确认方案及其成果 | 探索页区域、云量、图源、列表与选中影像 | 当前会话总结、右侧成果、打开真实工程/文件 |
| 探索页助手 | 当前区域、来源、日期/云量、列表、筛选与选择 | 历史工程或其他任务作为当前检索结果 | 当前会话确认卡、地图预览、任务/工程；可主动转到会话页 |
| 我的数据助手 | 当前打开的工程 ID；未选工程时为工程列表 | 旧探索区域、第一条历史工程作为当前工程 | 原工程及其实际文件，打开成果预览 |
| 工作区助手 | 当前文件/工程的原生 ID | 旧地图筛选、未打开的文件作为当前文件 | 原生检查与相同任务的成果预览 |
| 任务页助手 | 当前任务 ID；未选任务时为任务列表 | 第一条历史任务作为当前任务 | 状态、错误原因、必要的人类决策与实际输出 |

设置、账号及监测页说明自己的功能；监测使用实际官方服务状态及原生监测确认流程，不借用探索页状态。

## 同一任务的完整链路

1. 本轮请求记录入口、当前对象和只读工作区快照。每次提问刷新，已有方案保持原范围。
2. 普通检索问答直接使用当前列表摘要。全部检索数、筛选数、已选择数、可见图层数及部分/完整检索状态分别报告。未知不等于零。
3. 选中/显示/当前影像通过 `geod_catalog_selection` 从受支持来源重新读取准确 ID，创建原生检索凭据，不接受模型提供的 URL 或替换影像。空、过大或失效选择返回可纠正原因。
4. 需要用户决策的来源/范围/处理选择使用选项卡。原始影像选择与覆盖整个行政区的任务分别处理；面积成果仍需真实边界、覆盖检查和原生处理方案。
5. 完整方案提供地图预览和确认。明确开启原生完全访问才可免除确认；入口切换、选项回答和隐藏面板不授予执行权限。
6. 执行由原生任务负责。每份方案保存生成时的入口和范围，确认后后台继续使用它，后续改页面/筛选不改写任务。关闭侧栏只隐藏界面；停止响应或暂停目标是单独操作。
7. 原生状态及真实文件验证通过后才显示完成和成果。失败保留目标、原生任务与确认记录，按原因继续/修改/重试，不伪造完成。
8. 用户主动“在会话页继续”、从任务打开工程/任务页，或从历史选择任务时保留同一会话及方案。普通导航恢复对应入口的会话和草稿，避免串场景。

## 实现与验证边界

入口数据与原生凭据分别存在：`agent/scenes.mjs` 管理入口契约；`startup.js` 生成当前页面引用；Agent 面板管理入口会话和草稿；原生选择读取校验来源、日期、云量与实际 ID；原生确认与成果校验仍使用既有任务引擎。

回归覆盖入口恢复、草稿隔离、显式任务交接、后台任务的固定范围、关闭面板不中断、列表选择和下限云量校验。在线验收只读取公开目录、原始文件元信息并生成待确认方案/地图预览，不自动提交下载。自动化传递/执行测试和具体模型的措辞表现是两种不同证据。
