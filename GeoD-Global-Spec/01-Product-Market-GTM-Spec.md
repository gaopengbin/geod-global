### 0.3 商业与竞品前提修正

**不是无人区。** Copernicus Browser 已有搜索、比较、分析和下载；QGIS 插件目录也有按区域、日期、云量下载 Sentinel/Landsat 并生成 GeoTIFF 的工具。[S05][S08][S09][S10] GeoD 必须靠跨源一致性、可靠任务、本地成果和可重复交付形成差异，不能只靠“有 Sentinel 下载按钮”。

**旧竞品名称需更新。** Planet 已公告旧 EO Browser 与 Sentinel Hub Dashboard 于 2026-03-20 停用，并指向 Planet Insights Platform；开放数据用户可使用 Copernicus Browser。不能继续把旧 EO Browser 当作当前未变化的入口。[S06][S07]

**付款成功不等于钱已到银行。** 商户准入、交易处理、结算打款、汇兑、退款、税务、账号审核是不同环节。MoR 也不等于所有业务类型都可售，或解决卖家全部税务。[P01–P11]

## 1. 产品战略与边界

### 1.1 品牌与定位

工作名沿用 **GeoD**；`Global` 是发行与体验定位，不强制成为品牌名的一部分。保留现有品牌积累，域名与商标须独立核查，不假定任何新域名可注册。

建议副标题：**Geospatial Data Workspace**。比单纯的 Downloader 更完整，也比“AI GIS OS”更具体。

官网主标题建议：

> **Get the geospatial data you need.**

说明：

> Find, preview, process, and export imagery, elevation, vector, and 3D data in a local-first desktop workspace.

公开文案只列发布版本实际支持的能力；目标设计不直接当营销承诺。

### 1.2 核心任务

用户输入 **区域 + 数据类型 + 时间/质量要求 + 输出目的**。GeoD 给出候选、预览与限制，形成明确任务，并交付可被下游软件读取、可追溯和可重跑的文件。

产品主链：

`Area → Discover → Inspect → Compare → Prepare → Export → Reuse`

“处理”不强迫出现在每次操作中。只下载一个文件的用户直接下载；批处理用户可进入配方和 CLI。

### 1.3 不做什么

不做完整 GIS 编辑器、摄影测量重建平台、地籍确权系统、自动驾驶地图、安全关键导航、通用聊天软件；不以全球实时高清卫星、无限离线下载、任意商业影像再分发为卖点；不把三维查看等同于三维重建；不为了收费强迫开放数据绕行 GeoD 云端。

AI 是可选操作入口，GeoD Cloud 是可选托管服务，二者都不能成为本地任务的强制依赖。

### 2.1 本次能确认什么

| 证据 | 已确认内容 | 能支持的结论 | 不能支持的结论 |

| Copernicus Browser [S05] | 数据搜索、可视化、比较、分析和下载 | 免费官方工具是强替代品 | 浏览器工具无法处理真实任务 |
| Earth Search [S01] | 标准化 STAC 和多个开放数据集合 | 跨数据源产品有可复用基础设施 | 所有资产都免认证、免费流量、具有 SLA |

这是**定性证据与竞争供给证据**，不是完成的市场规模调查。本文不提供未经调查的 TAM、搜索量、市场占有率或收入预测。

### 2.2 要验证的真实问题

不是问“喜欢这个软件吗”，而是问：上一次交付数据用了哪些网站、脚本、插件？哪一步失败？发生多频繁？谁支付工具费？是否允许云服务看到项目范围？能否展示去敏后的实际输入与输出要求？

重点验证五个假设：

| ID | 假设 | 强证据 | 推翻条件 |
|---|---|---|---|
| H01 | 多源数据准备比单一卫星浏览更有差异 | 同一任务需要至少两类数据并重复执行 | 大多数任务只需官方 Browser 一次导出 |
| H02 | 本地可靠执行有价值 | 用户有大文件、断网、磁盘、失败恢复的真实成本 | 用户只要网页截图，不需要本地文件 |
| H03 | 可重复配方有留存 | 用户带着同一配方再次处理新区或新日期 | 一次性需求占主导且不再复用 |
| H04 | 托管协作有人付费 | 有预算者明确需要共享、审计、通知或运行治理 | 本地 JSON/Git 足够，云服务没有新增价值 |
| H05 | 独立客户端减少操作摩擦 | 同一任务盲测减少步骤和返工 | QGIS 插件表现相当且没有切换理由 |

访谈建议覆盖 18 位潜在用户：6 位小团队 GIS/环境咨询人员、6 位数据/科研开发者、3 位地图产品开发者、3 位制图/教育或三维场景人员。人数是研究计划，不是已访谈记录。招募与研究记录模板见附件三。

## 3. 客群、购买者与场景

不把“海外”当成一种审美或一个付费市场。按任务、预算和采购方式分群，地区用于语言、支付、时区和法规适配。

| 客群 | 典型任务 | 现有替代 | 谁买单 | 推荐价值主张 | 付费假设 |
|---|---|---|---|---|---|
| 小型 GIS / 环境咨询团队 | 多个项目区反复交付影像、DEM、矢量 | QGIS + 官方平台 + 脚本 | 负责人或项目经理 | 同一区域、多源、可验收、可复用 | 共享配方、版本、运行审计、专业支持 |
| 地理空间开发者 | 为应用准备 COG/PMTiles/矢量数据 | 命令行、脚本、对象存储 | 自己或技术负责人 | 桌面配置转 CLI，输出标准格式 | 托管工作区、团队配置和运行管理 |
| 科研/ML 用户 | 按时空条件构建可复现数据集 | Notebook、云平台 | 实验室/课题预算 | 固定输入、掩膜、来源和处理版本 | 团队服务与部署；个人免费需求可能更强 |
| 制图、教育、设计用户 | 获取单个区域的可用成果 | 浏览器、QGIS、手工拼接 | 个人/学校/工作室 | 看得懂的输出预设 | 以免费增长与一次性交付服务为主，不强推年费 |
| 大机构 | 私有数据、代理、内网、统一部署 | 企业 GIS 平台 | IT/采购/法务 | 可审计、自托管、无外传 | 销售周期和合规成本高，不默认靠它快速获客 |

### 3.1 地理与语言策略

英文为全球主语言；优先通过英语地理空间社区招募，不根据国籍推断需求。可将美国/加拿大、英国/爱尔兰、澳大利亚/新西兰和使用英语协作的欧洲团队设为调研样本来源，**这不构成已经验证的销售优先级**。

界面完整支持地区设置、24/12 小时制、公制/英制、ISO 日期与时区说明；坐标、CRS 和数据采集时间保持专业语义，不能随本地化改变数据含义。之后是否增加德语、法语、西班牙语、葡语，由真实需求和维护能力决定。

### 3.2 三个旗舰使用故事

**项目区交付包**：同一多边形获取影像、DEM 和道路/建筑矢量；得到一个带来源说明的文件夹，而不是一张混合截图。

**重复遥感工作**：选择日期范围与质量规则，生成固定网格上的影像/指数序列；无合格观测时留下空缺说明，而不是伪造“每 15 天必有一景”。

**开发者打包**：交互验证数据与范围，导出同一任务配方，在本地或用户自己的 Runner 中批量执行，再把成果交给 QGIS、Python 或地图应用。

## 4. 竞争位置：做互补层，不靠贬低替代品

| 替代品 | 官方可确认的强项 | GeoD 需要验证的差异 |
|---|---|---|
| Copernicus Browser [S05] | Sentinel 发现、预览、比较、分析、下载 | 更多数据类别、稳定的本地任务、跨源交付包与配方 |
| Planet Insights Browser [S07] | 影像分析、可视化、比较、输出与统计 | 不绑定单个商业平台，使用用户已有数据和授权 |

## 5. 产品家族：独立仓库，版本化复用

**现行决定：两个独立产品仓库。** Global 在 `G:\code\geod-global` 维护自己的源码、依赖锁文件、配置、测试、CI、构建和发布；国内版继续留在 `G:\code\tif-downloader`。不将国内工作树复制、移动或改造成 Global 的工作区，不以国内版分支承载海外版。

```text
国内版仓库：自己的界面、配置、依赖、构建与发布

Global 仓库：Area + Dataset + Recipe + Artifact
    ├── Desktop（核心产品）
    ├── CLI / MCP（同一 Global 契约与任务服务）
    └── 产品网站 / 可选云协作入口

未来可选：版本化 Core / Contracts / Provider 库
    └── 各产品独立选择已验证版本与升级时间

Optional hosted services：GeoD Cloud Workspace / Teams
```

当前原型是 Global 的交互设计基础。产品最终以 Tauri 桌面和 Rust 原生处理为核心，公开网站承担介绍、下载与文档，可选 Web 管理台承载经过决策的协作服务；浏览器原型不等于已经实现完整纯 Web 产品。

共享核心是未来的包依赖关系：允许使用发布版本、固定提交或可校验的版本化产物；禁止跨仓相对源码导入、`file:`/`link:` 指向国内工作树、国内 `node_modules` fallback，以及运行时去相邻仓库寻找工具。任何抽取须另行明确来源、许可证、版本、接口和测试，Global 不读取国内未提交改动作为构建输入。

发行版使用独立 application identifier、设置命名空间和更新通道。数据迁移由用户选择；数据库升级先备份，不让一个版本升级直接破坏另一个版本。开放配方和成果文件保持跨版本兼容。

## 6. 信息架构与全局对象

### 6.1 稳定导航

主导航：**Explore / Workspace / My Data / Tasks / Sources**。裁剪从地图或文件直接发起；已保存的裁剪方案仅在 My Data 的折叠高级区管理，不占一级入口。Settings、Help、账户与可选云服务放底部。Satellite、Imagery、Elevation、Vector、3D 是 Explore 的数据分类，不再各自拥有相互隔离的 AOI 和任务系统。

Workspace 是工作上下文，不是必须注册的云项目。用户可以使用自动保存的 `Untitled workspace`，不用先创建项目才能下载。

### 6.2 主屏布局

```text
Top bar：Workspace name | Search places, datasets and commands | Account/Help
Navigation rail | Discovery / Layers | Map / 3D / Compare | Inspector
Bottom：Contextual timeline / Tasks drawer / Coordinates and attribution
```

地图是工作面，左侧负责发现和图层，右侧负责当前对象。详情栏、时间轴、任务抽屉按需出现；避免四个重面板一直挤占地图。

### 6.3 七个核心对象

| 对象 | 内容 | 关键规则 |
|---|---|---|
| Area | 多边形/多多边形、来源、原始 CRS、名称 | 跨模式共享；不可悄悄替换为 bbox |
| Dataset | 数据集合与产品说明 | 数据集不是一份文件，也不是一个图层 |
| Scene / Item | 观测时刻、footprint、资产清单 | 记录实际采集时间与产品版本 |
| Layer | 显示状态、样式、数据引用 | 调色不自动改变原始科学数值 |
| Recipe | 查询、选景、处理、输出声明 | 可版本化、可预检，不包含密钥 |
| Job | 某次执行及其输入快照 | 状态与输出可恢复，不只是一条进度条 |
| Artifact | 已交付文件/文件集合、检查结果、来源 | 删除库记录与删除磁盘文件严格分离 |

| Workspace | 图层、AOI、地图、Inspector | 拖入数据、对比、调整显示 | CRS 不明、GPU 失败、数据缺失 |
| Dataset / Scene inspector | 数据、许可、波段、网格、访问方式 | 查看资产、下载、进入处理 | 需登录、Requester Pays、仅预览授权 |
| Compare | 双视图、卷帘、透明度、闪烁 | 固定两份数据、同步视图 | 不同分辨率/日期/产品级别的提示 |
| Processing | 操作链、输入检查、参数、输出 | 预览结果、保存配方、执行 | 缺波段、网格不一致、不可执行算子 |
| Export review | 数据语义、格式、CRS、空间和费用预估 | 确认执行、回到参数 | 不支持格式、覆盖文件、超额度 |
| Tasks | 执行阶段、日志、失败项、成果链接 | 暂停/恢复/取消/重试 | 不可暂停阶段、崩溃恢复、部分成功 |
| My Data | 列表/网格、搜索、区域、格式、来源 | 查看、打开目录、重跑 | 文件移动、校验失败、只剩记录 |
| Recipes | 版本、所需能力、预检、历史运行 | 导入、导出、批量区域、计划执行 | 缺依赖、不可信配方、模式升级 |
| Sources | 官方目录、用户自定义、连接与许可 | 测试连接、认证、禁用 | URL 错误、限流、许可不明、撤销令牌 |
| Cloud Workspace（可选） | 同步设置、版本、运行通知、额度 | 选择同步范围、连接 Runner | 离线、冲突、远端不可用 |
| Organization（可选） | 成员、角色、共享配方、审计 | 邀请、移除、转移所有权 | 无权限、最后一位 Owner、删除组织 |
| Billing（可选） | 计划、真实权益、发票、取消 | Checkout、恢复购买、门户 | 支付未确认、退款、扣款失败、争议 |
| Settings / Support | 语言、单位、主题、缓存、网络、日志 | 清缓存、导出脱敏诊断 | 不能连带删除用户成果 |

所有异步页至少设计 empty、loading、ready、partial、error、offline 六种状态。用户权限不够时解释缺失能力与可执行替代，而不是无意义灰按钮。

## 8. 六大数据域的完整能力

### 8.1 Satellite：场景到分析数据

完整支持场景发现、时间与质量筛选、波段读取、可视化预设、指数、质量掩膜、重投影、同网格输出、时间序列与多景合成。搜索结果提供列表与表格切换，不用大缩略图卡片牺牲专业用户筛选效率。

查询至少包含 AOI、时间、集合、产品级别；云量、轨道、覆盖比例等依赖数据源能力。**整景云量与 AOI 内云量必须分开**，未计算 AOI 内云量就不得用其名义排序。所谓“最清晰”需用户选择评价规则，不能由一个未知的综合分数替代。

预设为 Natural color、False color、NDVI、NDWI、Custom。每个预设绑定具体波段语义、公式、单位和适用集合，而不是跨卫星硬套 B04/B08。处理前检查 scale/offset、NoData、掩膜与目标网格；把用于显示的拉伸和用于导出的科学数据分开。

对 SAR 不显示光学云量选项；几何校正、辐射定标、去斑等作为有验证要求的独立处理能力，不承诺只拿到 GRD 就等于分析就绪。MODIS/VIIRS 等产品经目录能力和处理组件扩展，不在 UI 中伪装成同分辨率真彩色影像。

### 8.2 Imagery：连续地图与历史版本

支持配置 XYZ/TMS、WMTS、WMS、ArcGIS 图像/地图服务及历史图层。所有服务先查询能力与授权；**WMS 请求图像不等于 XYZ 瓦片，渲染 RGB 不等于原始多波段遥感产品**。

瓦片网格显式记录 tile size、CRS、matrix set、原点、分辨率、XYZ/TMS Y 方向和 zoom offset。WMTS 不能仅把 URL 换成 `{z}/{x}/{y}`。预览与导出使用同一坐标模型，避免512像素/级别偏移“看起来正常、导出错位”。

历史影像保存服务发布日期与采集时间，两者分开；缺少采集时间显示 unknown。比较同区域不意味着不同年份一定更新了影像。

### 8.3 Elevation：高程和派生成果

支持 DEM/DSM 数据获取、区域拼接、阴影、坡度、坡向、等高线、剖面和地形预览。数据源标明 surface type、水平/垂直参考、单位和原始分辨率；不把所有高程数据当裸地 DTM，也不靠上采样声称提升真实精度。

坡度、距离与面积计算需选择正确度量或投影；派生操作记录参数。不同垂直基准不能无提示拼接。输出含单位、NoData、处理履历，剖面可导出 CSV。

### 8.4 Vector：要素与瓦片分开

要素路径包括 OSM 区域要素、GeoJSON、GeoPackage、SHP、WFS/OGC API Features、ArcGIS Feature Service；瓦片路径包括 MVT、PMTiles、MBTiles。PMTiles 是封装/访问形式，不是数据源，也不赋予数据授权。[S13]

OSM 提供 Buildings、Roads、Water、Land use、POIs 等预设，但须处理关系、多几何、分页和去重。大区域采用合适的抽取数据或自有服务，不把公共接口当无限后台。瓦片要素可能经过切片、简化或缺字段，不应直接宣称等价完整原始要素。

格式转换只在有明确数据语义时开放。GeoJSON 到 PMTiles 需要制瓦片、层名、缩放与样式设计，不是改扩展名。属性表支持过滤与抽样预览，不能一次性把百万条记录加载进 DOM。

### 8.5 3D：授权资产获取与预览

复用现有 3D Tiles 工作，完整目标包含远程/本地 tileset、glTF/GLB、地形与点云适配。3DGS 作为需单独验证的 renderer/格式能力，不能笼统宣称所有 PLY 都支持。

必须区分：**按区域选择相交瓦片**与**几何精确裁切模型**。前者的成果可能超出 AOI，界面和 metadata 要解释；后者需要另一个处理器。纹理、外部引用、变换、隐式切片与依赖完整性纳入验收，不以根 tileset 下载成功判定全部成功。

Google Photorealistic 3D Tiles 不作为默认可离线导出的示例。官方 Map Tiles API 有缓存、提取与离线使用限制；是否例外应依实际协议，不由一个 API Key 决定。[S12]

### 8.6 Local Data：本地文件也是一等来源

支持打开、检查、预览、转换和登记本地 GeoTIFF/COG、矢量、瓦片包、3D Tiles。无需 GeoD 账号、网络或云端鉴权。

导入 SHP 时识别同名配套文件与 CRS，未知 CRS 不猜。文件可引用，不默认复制；用户选择“托管到 GeoD 数据目录”才复制。大文件使用窗口读取、分级预览或旁车处理，不全量进入 WebView 内存。

### 9.2 能力与许可是两张表

技术能力：`search / thumbnail / map_preview / asset_read / asset_download / server_process / local_process / time_series / cancellation`。

授权策略：`interactive_preview / http_cache / bulk_download / offline_use / derivative_export / commercial_use / redistribution / third_party_processing`。

每条授权取值为 **allowed / restricted / forbidden / unknown**，附证据、条件、适用账号/计划、审查日期。`unknown` 不渲染绿色勾。已知禁止不能通过“我已知情”按钮变为允许。

最终按钮可用性：

`技术支持 ∩ 当前认证 ∩ 数据授权 ∩ 产品可执行性 ∩ 用户权限`

### 9.3 Provider SDK 和目录治理

manifest 包含 provider ID、版本、支持的 collection、认证方式、域名范围、能力、许可引用与维护信息。查询统一为类型化对象，底层接口差异留在 adapter。

官方目录条目走评审与签名分发；社区目录清楚标注来源。普通 Provider 配置不允许任意执行代码；需要原生驱动时采用独立签名能力包与权限确认。网络重定向重新校验目标，不能把第三方 URL 变成任意本地/内网读取通道。

访问健康分为目录状态、认证状态和资产状态；不能因元数据搜索成功就显示“下载正常”。密钥进入系统凭据库，导出配置自动去除 secret、签名参数和账号标识。

## 10. 统一 AOI、时间与比较系统

### 10.1 AOI

支持矩形、多边形、多多边形、坐标输入、当前视图、地名/行政区和文件导入；保存常用区域；批量导入区域表与文件。

内部至少保存原始 geometry/CRS 与规范化查询 geometry。处理跨日期变更线、极区、洞、自交、无效坐标与大范围；面积使用适合的地理计算，不能用屏幕矩形面积替代。多个任务引用不可变 AOI 快照，之后修改工作区区域不影响正在运行任务。

### 10.2 时间

区分 acquisition datetime、processing datetime、catalog updated、map release date。产品缺少精确时间时保留其精度，例如年、月、日期，而不是补零伪装成精确观测时刻。

按月/每 N 天选景是窗口规则：空窗口、跨场景拼接、多个候选都必须有明确处理策略。自动重跑时锁定查询规则；需要结果完全相同则冻结场景 ID 与资产版本。

### 10.3 比较

Swipe、Side by side、Opacity、Flicker 共用两个显式选择的数据对象。同步的是地理范围，不是相同 zoom 数字。比较不同传感器时显示像素大小、日期、处理级别与配色，不把简单图像差当可靠变化检测。

## 11. 处理、导出与交付包

### 11.1 处理图

目标支持下载、选择波段、掩膜、裁剪、重投影、重采样、拼接、表达式、地形派生、矢量筛选、转换和打包。处理节点声明输入类型、输出类型、参数 schema、依赖、可取消性、资源估算与验证方法。

处理位置显式为 **Local / Provider / User runner**。本地模型无法完成的操作不得悄悄切云端；涉及数据上传、AOI 外传和第三方计费时先说明。

### 11.2 输出中心

| 输入域 | 目标输出 | 必须保留/检查 |
|---|---|---|
| 渲染影像 | GeoTIFF、PNG/JPEG + 可选定位旁车 | 说明 RGB 渲染，不是原始光谱 |
| 科学栅格 | GeoTIFF/COG、多文件/波段集合 | dtype、scale/offset、NoData、单位、CRS、网格 |
| 高程 | DEM、派生 GeoTIFF、等高线/剖面 | 垂直参考与单位；派生参数 |
| 矢量要素 | GeoPackage、GeoJSON、按需 SHP | 属性、几何、编码、CRS；SHP 限制提示 |
| 瓦片 | PMTiles、MBTiles、允许的瓦片集合 | tile matrix、元数据、样式依赖与署名 |
| 三维 | tileset 与资产集合、相应模型格式 | 引用、变换、纹理、外部依赖、许可 |

COG 不是给 TIFF 改名，应按其布局、分块、overview 等要求生成并验证；GDAL 有对应驱动，但依赖打包与跨平台测试仍是工程工作。[S16]

### 11.3 交付包

建议输出结构：

```text
project-area-export/
  data/
  previews/
  metadata.json
  recipe.json
  sources.json
  validation.json
  checksums.sha256
  README.txt
```

`metadata.json` 包含区域、输入产品 ID、时间、波段、数值语义、CRS、分辨率、引擎/配方版本、操作链、许可引用、实际输出列表和校验摘要。兼容 STAC 的成果可额外导出 STAC Item，不能把任意 metadata.json 宣称为符合 STAC。

可选生成 QGIS 样式或简单报告，验证后才列为兼容。GeoD 不对源数据的测绘精度、项目验收法律效力作自动保证。

## 12. 任务与存储：可靠性是产品功能

### 12.1 状态机

```text
Draft → Validating → AwaitingApproval → Queued → Running
                                           ↕ Paused
Running → Succeeded | Partial | Failed | Cancelled
Startup → Recovering → ResumeCandidate | NeedsReview
```

审批用于成本、外传、覆盖和高风险操作，不是每个下载都要用户点三次。只有明确可安全暂停的阶段才显示 Pause。

### 12.2 任务协议

每个 job 保存输入快照、策略版本、阶段、进度度量、已完成资产、临时目录和日志。网络恢复按协议能力使用 Range/校验信息；不支持断点的资产标明重下，不能显示“已续传”却从头计算。

阶段失败按指数退避和服务端 Retry-After 处理；限流不靠无限加并发解决。认证过期暂停等待恢复，许可禁止直接停止，no coverage 不当网络错误反复重试。

成功条件是所有必需输出完成校验。可选结果失败可以 Partial，但必须展示缺失项。进度区分未知总量、阶段比例与字节比例，不伪造剩余时间。

### 12.3 磁盘与缓存

**Cache / Runtime / User outputs** 三区分离。缓存有持续执行的容量上限；活跃任务文件不可被回收。写入采用唯一临时路径与完成后的原子提交；空间不足暂停而不是闪退。

卸载默认保留用户输出，删除成果必须单独授权。批量清理先预览目录与大小，检查标记与归属；取消作业不等于删除用户已有文件。

## 13. 技术架构与引擎决策

### 13.1 目标结构（不是当前目录）

```text
apps/
  desktop-cn/
  desktop-global/
  website-global/
  cloud-console/       # optional service UI
crates/
  geod-core/
  geod-contracts/
  geod-providers/
  geod-jobs/
  geod-raster/
  geod-vector/
  geod-tiles3d/
  geod-cli/
packages/
  design-tokens/
  workspace-contracts/
  viewer-adapters/
  provider-manifests/
services/
  control-plane/       # optional auth, metadata sync, teams
  billing-adapter/     # payment provider independent
```

先抽离纯业务与稳定契约，禁止 UI 为了 Global 再复制一份下载、任务或投影代码。GDAL/PROJ/其他原生组件的发行与许可证清单单独管理，不假定 Rust crate 会自动带齐所有动态库。

### 13.2 Viewer 选择

**推荐设计**：Global 的专业二维工作区采用 OpenLayers adapter，利用其 COG、多波段等能力；Cesium adapter 服务三维；现有 Leaflet/MapLibre 继续保障既有产品与迁移。OpenLayers 官方 COG/NDVI 示例证明相应预览能力存在，不证明 GeoD 已接入或性能已达标。[R03][S14][S15]

不是所有引擎同时叠一屏。由工作模式启用所需 renderer，共享 camera extent、AOI、selection 与 layer 描述；释放失活 WebGL 资源。MapLibre 是否保留在 Global，由矢量样式一致性测试决定，而不是因为已有依赖就再增加一个常驻引擎。

**决策门禁**：用同一组大 COG、多波段、WMTS、多投影、PMTiles/MVT 和普通 XYZ 样例验证；若适配成本/性能不达标，保留现有二维 adapter，不能卡住数据核心与产品规格。

### 13.3 原生处理

UI 只发类型化 job；处理在 Rust 任务引擎及必要的独立 worker 内执行。大文件与原生库崩溃不应带走 UI。WebView 与本地服务使用最小授权，不开放无认证的通用文件读取、shell 或跨域代理。

## 14. Recipes、CLI 与 MCP

### 14.1 Recipe 契约

配方是声明式任务，不是未经审核的 shell。保存 schema version、AOI、Provider/collection、选择规则或固定 Item、处理图、输出、资源预算与许可策略。import 先预检，未知版本、外部脚本、远端计算、收费资产和覆盖行为要显式说明。

分享配方不分享登录凭据、完整敏感 AOI 或私人文件路径。公开前给用户看将上传的字段。

### 14.2 CLI 目标契约

以下是**待实现的命令设计，不代表当前版本可执行**：

```bash
geod sources list --json
geod search --recipe search.recipe.json --json
geod plan job.recipe.json --json
geod run job.recipe.json --dry-run --json
geod run job.recipe.json --json
geod tasks list --json
geod tasks inspect <job-id> --json
geod tasks cancel <job-id>
geod artifacts validate <artifact-id> --json
```

stdout 只输出结构化结果，诊断写 stderr；长任务可输出 NDJSON events。exit code 区分成功、无数据、参数、认证、许可、部分成功和执行失败。非交互模式不弹登录窗口或偷偷接受付费，返回可处理的状态。

### 14.3 MCP / Agent

MCP 是薄适配层：search、inspect、plan、submit_job、job_status、cancel、list_artifacts。长任务先回 job ID，不能在一次调用中无限等待。工具返回包含来源、限制和实际状态，AI 无权绕过授权、预算或文件覆盖确认。

复用 CLI/Core，不维护第二套 AI 专属处理器。`cesium-mcp` 可以作为展示/互操作伙伴，但 GeoD 不依赖它才能下载或执行基本任务。

## 15. AI：可选辅助，不成为成本与地区单点

建议入口是命令面板与可收起助手，不让聊天窗口替代地图。自然语言转换为可审查配方，执行前显示区域、数据、费用、外传与输出。用户可回到表单修正，所有结果回归普通 Tasks/My Data。

模型提供者可配置；未接入模型仍有全部基础数据功能。本地可用 CLI/Agent 的接入需逐客户端验证，不假定 ChatGPT 订阅可作为产品后端 API，也不依赖用户不能稳定使用的官方 API 区域入口。

不向模型发送全量数据或完整路径作为默认上下文。索引公式、波段、许可判断和执行状态以工具返回为准；“AI 说完成”不能替代 Artifact 验收。

## 16. 视觉与交互设计系统

### 16.1 风格不是“外国人都喜欢什么”

视觉目标针对长时间使用数据工具的用户：**安静、清晰、准确、可扫描、地图优先**。不直接复制 Linear/Mapbox 的外观；用真实影像、剖面和数据层级建立识别度。

采用 Light + Dark + System；保持 GeoD 蓝色品牌连续性。强调色只承担选择与主操作，错误、警告、许可状态不只靠颜色。没有满屏渐变、装饰性地球、发光 KPI 卡片或 AI 吉祥物。

### 16.2 设计 Token（CSS px / 建议值）

| 类别 | 规格 |
|---|---|
| 正文字体 | Inter 或系统无衬线；坐标、ID、日志用等宽字体；确认字体许可 |
| 默认字号 | 正文/输入 14，常用标签 13，辅助信息 12，标题 16/20/28 |
| 最小信息字号 | 关键操作不低于 12；不再使用 11px metadata 作为通用默认 |
| 行高 | 正文约 1.45–1.6，紧凑表格按内容验证 |
| 间距 | 4/8/12/16/24/32，避免任意散值 |
| 控件高度 | 普通 36，紧凑列表行 32–36；大触控模式 44 |
| 圆角 | 输入 6、面板 8、对话框 12，不把所有面板做成大圆角卡片 |
| Light | 背景 `#F6F7F9`，surface `#FFFFFF`，文字 `#17212B`，边界 `#D8DEE7` |
| Dark | 背景 `#14181F`，surface `#1C222B`，文字 `#E8EDF3`，边界 `#394350` |
| Accent | Light `#2563EB`，Dark `#7AA7FF`；各交互态最终测试对比度 |
| 动效 | 一般过渡 120–180ms；支持减少动态效果 |
| 图标 | 一套 SVG 图标；主要操作带文字，未知图标有可访问名称 |

这些颜色和尺寸是初始 Token，不代表已通过可访问性审计。参照 WCAG 2.2 检查文字对比、非文字状态、焦点、键盘与目标尺寸；原生桌面还需跨 WebView 验证。[S18]

### 16.3 布局和快捷键

以 1440×900 为常用设计画板：导航约 52px、左面板 288px、右 Inspector 304px、顶部 52px；左右可拖动、可折叠。窄于 1280px 自动收起次要面板，地图不缩成邮票。支持 100/125/150/200% 系统缩放和长英文标签。

`Cmd/Ctrl+K` 命令面板，`Esc` 退出当前绘制/临时模式，常用快捷键在菜单可见。不能让文本输入期间触发地图热键；地图之外应能用键盘完成搜索、选景、参数与导出。

### 16.4 国际化文案

采用简单英语与句首大写，不使用生硬直译。主界面为 Area / Date / Data / Resolution / Export；STAC、CRS、COG、资产 href 放到需要它们的上下文里，但不隐藏影响正确性的专业参数。

数量、单位和日期明确。错误应包含原因、受影响内容和恢复动作，例如 `The source requires authentication. Sign in to continue.`，而不是只显示 `Error 403`。

## 17. 隐私、安全、离线与发行

### 17.1 Local-first 的真实含义

成果和处理默认保留本机，**不代表零网络外传**：目录搜索会向 Provider 发送 AOI/时间；地图请求也会暴露所查看区域。Sources 页和第一次远端处理应说明接收方与字段。

使用本地功能不强制创建 GeoD 账号。可选云同步默认不传原始栅格、完整日志、凭据或文件内容；同步 AOI、配方也可能包含敏感信息，需显式选择。

遥测默认关闭或使用清楚的首次选择，不将拒绝遥测与核心功能绑定。记录经同意的粗粒度功能事件，禁止上传精确坐标、场景资产签名 URL、文件路径和提示词正文。崩溃包先自动脱敏并允许用户预览。

### 17.2 安全与合规设计

秘密放系统凭据库；OAuth 桌面流使用适合 public client 的机制，不内置可重复使用的客户端 secret。云端权限在服务端校验；外部链接、配方导入和社区驱动视为不可信输入。分享链接默认私有、可撤销，可选择过期。

网站与服务需明确经营者、Privacy、Terms、退款/取消、第三方数据条款、分包处理者和支持渠道。面向相应地区时，由合适专业人员检查隐私、消费者保护、跨境收款和税务义务；本文是设计清单，不是法律合规认证。

### 17.3 发布能力

Windows 签名、macOS 签名与 notarization、Linux 包、校验和、SBOM、更新签名、渠道隔离和回滚都列入发行规格。Tauri updater 的更新签名与操作系统代码签名是不同环节，不可互相替代。[S17]

发布附真实兼容矩阵与已知限制；下载页自动推荐操作系统但保留手动选择。提供稳定/预发布通道，不能把试验原生库自动推给全部用户。普通退出提示未完成任务；恢复能力不靠用户记忆。

## 18. 性能与可靠性验收目标

以下为目标预算，需明确测试机、数据集、网络与缓存条件后验收，不是当前性能宣传。

| 指标 | 设计目标 | 测试边界 |
|---|---|---|
| 桌面冷启动到可交互 shell | p95 ≤ 4 秒 | 参考机：16GB RAM、SSD；不等待远程目录 |
| 常见操作视觉反馈 | ≤ 100ms | 指选择/按钮反馈，不把网络处理算进去 |
| 缓存命中的中等数据预览 | p95 ≤ 2 秒 | 固定样例、显示分辨率和测试 GPU |
| 新检索到首批结果 | 单独测客户端/Provider耗时 | 不替公共 API 承诺时延 |
| 结果列表 | 10,000 条元数据可虚拟化浏览 | 分页获取，不一次拉全远程结果 |
| 大栅格 | 文件大小不直接决定 UI 常驻内存 | 窗口读取与金字塔，测试峰值内存 |
| 正确性 | 所有必需输出通过格式/空间/数值验证 | 坐标和数值错误优先于速度 |
| 恢复 | 可恢复阶段断网/杀进程后不丢已确认成果 | 对不支持恢复阶段明确标注 |
| 可访问性 | 主要操作键盘完成，文字缩放布局可用 | 三平台真实 WebView 测试 |

不统一承诺“任务都能断点续传”，也不将上游永久删除的资产、许可撤销或用户磁盘损坏当成软件可恢复范围。

## 19. 商业模式：先保护开源承诺，再定义收费价值

### 19.1 推荐模型

**本节建议 GeoD Desktop + CLI + 本地 Recipes 保持免费开源，收费围绕可选托管软件服务、组织治理、运行保障和有边界的专业服务；这不是已确认的完整商业模式。**

第19–23节的产品矩阵、云订阅权益和价格按这一候选方案展开。既有发行权益保持；未来新增桌面 Pro/独立组件、Cloud/Teams、专业服务及组合仍需按[附件06](06-Decisions-Contracts-and-Release-Gates.md)比较和决定。表格中的“免费”或“付费”不自动构成对未来新功能的公开承诺。

这比此前笼统的“把批量/CLI 放进 Pro”更符合现有项目定位。MIT 文本允许使用、修改、分发和销售副本，附带保留通知等条件；它不提供把已有免费发行包改成“商业使用需买许可证”的依据。[R02]

新增闭源模块、换许可证或双许可属于另一个需要审查权利与贡献来源的决策，**本文件不替用户作出这一变更**。免费不等于没有收入；付费也不意味着可以买到第三方影像版权。

### 19.2 产品与收入分层

| Offering | 用户得到什么 | 收费方式 | 不包含什么 |
|---|---|---|---|
| GeoD Desktop | 本地发现、下载、处理、导出、批量、配方、CLI/MCP | 免费开源 | 上游商业数据、公共服务 SLA |
| GeoD Cloud Workspace | 私有配方/区域/元数据同步、版本、运行通知、连接自有 Runner | 软件订阅，价格待验证 | 默认不托管原始大影像，不含无限算力或 AI |
| GeoD Teams | 共享目录配置、角色、审计、团队配方版本、Runner 管理 | 按组织的订阅 | 不宣称能共享第三方账号授权；不默认云端代管密钥 |
| Deployment / Care | 安装配置、一次性流程交付、故障诊断、培训 | 定范围报价/支持合同 | 无限工时、保证上游数据存在、测绘责任保证 |
| Sponsorship | 支持开源维护 | 合适赞助渠道，资格待确认 | 不伪装成软件订阅，也不承诺特殊数据许可 |

**要验证的关键问题**：用户是否真需要云协作，而不是本地文件/Git 就足够。若没有，保留完整桌面产品，商业重心转向部署与支持，不为了订阅造一个没人需要的云层。

### 19.3 云端产品的明确边界

托管层是控制面，不默认成为数据流量中转站。数据从 Provider 到用户本机/自有 Runner；需要存档时优先用户自有对象存储并说明费用。

云端可保存 recipe versions、任务摘要、组织配置和明确同意的 AOI。Private recipe 分享支持 owner/editor/viewer；viewer 不等于得到上游数据权限。审计包括修改和运行，不记录密钥。

在本节候选方案中，本地定时执行免费，云端运行治理和通知作为付费服务。当客户端或用户 Runner 离线时显示等待，不承诺关机仍在本地运行。无人值守远端 Runner 使用最小权限、预算上限与批准过的配方，不能从云上执行任意 shell。

## 20. 定价设计与支付转化

### 20.1 候选价格，不作为正式报价

为研究提供有约束的价格卡，而非泛泛地问“愿意付多少”。建议测试：

| 方案 | 研究用价格 | 研究用权益边界 |
|---|---:|---|
| Desktop | $0 | 已发布的全部本地能力，无 GeoD 账号门槛 |
| Cloud Workspace | $12/月或 $99/年 | 1 位用户、私有配方/元数据同步、2 个已连接 Runner、100 条月运行记录；不含远端计算成本 |
| Teams | $39/月或 $399/年/组织 | 5 位成员、角色/审计/共享配置、10 个 Runner、500 条月运行记录；额外使用事先报价 |
| Setup service | $249/次起的测试报价 | 单一已约定工作流、一次配置与交付说明，范围固定 |
| Enterprise / managed deployment | 询价 | 自托管、采购要求、培训、支持范围按合同 |

容量数字同样是商业假设。按真实成本与使用研究校正，不把计数器做成惩罚正常操作的收费陷阱；仅控制托管服务资源，本地运行不因云记录额度耗尽被锁。

### 20.2 不推荐的默认模式

不提供“永久无限云资源”买断；不按免费卫星数据的每平方公里另收数据费；不把可绕过的前端功能锁当开源商业护城河；不靠在免费版人为放慢下载制造付费需求。

若将来销售独立商业桌面组件，可讨论永久版本与更新期，但必须单独明确代码/资产权利、离线激活和更新政策，不直接套用本文云订阅价。

### 20.3 试用、升级与取消

建议软件服务提供 14 天试用，不要求信用卡；只有托管功能显示试用权益。本地全部正常。试用期自动结束而不是隐性扣款。

升级页清楚写 software subscription 与 third-party charges 的区别；显示币种、税费处理、账期、续订和取消入口。价格由服务端 price ID 决定，桌面不接受任意金额作为订单依据。

取消订阅默认到期停止续费；到期后云端降为只读与导出宽限期，建议 30 天导出、之后按公开保留策略删除。退款、争议和服务终止不得删除本地成果，不能用不可访问成果迫使续费。

免费版不反复弹窗；升级触点只发生在用户需要真实的托管/团队能力时。

## 21. 单位经济：先知道一单剩多少

### 21.1 计算口径

下面只是**敏感性模型**，不是收入预测，也不是用户现有财务情况。以 $99 年付软件订阅为例，假设不含买家税、不含退款、使用 Paddle 公布的标准 `5% + $0.50` 费率估算。[P04]

| 单用户年度项目 | 假设金额 |
|---|---:|
| 产品收入 | $99.00 |
| 支付平台费 | $5.45 |
| 分摊托管成本 | $12.00 |
| 支持人工成本 | $20.00 |
| 退款/争议损失准备 | $5.00 |
| 固定成本前贡献 | **$56.55** |

支持人工 $20 是预算假设，不是无限售后；按 $25/小时估算仅相当于 48 分钟/年。超出需提高价格、减少支持范围或改为专门服务。

实际计费基础可能涉及含税金额、费率合同、退款手续费、汇兑、打款与银行成本。买家税、支付平台扣款、合同收入、银行到账和利润不得混为一谈。

### 21.2 年度情景，不是增长预测

假设固定运营支出 $160/月（$1,920/年），不含开发者工资、所得税、初始设计/法务/签名费用。

| 年付用户数 | 产品收入 | 平台费 | 变动成本与准备金 | 固定成本前贡献 | 扣假设固定成本后 |
|---:|---:|---:|---:|---:|---:|
| 50 | $4,950 | $272.50 | $1,850 | $2,827.50 | $907.50 |
| 200 | $19,800 | $1,090 | $7,400 | $11,310 | $9,390 |
| 500 | $49,500 | $2,725 | $18,500 | $28,275 | $26,355 |

按此假设，覆盖固定运营支出约需 34 位年付用户；若再加入 $12,000/年开发者收入目标，约需 247 位。**这不证明能获得这些用户，只展示商业模型对获客、成本和支持的要求。**

年度预收款不等于当月利润，年付订阅应另算服务履约、退款准备和收入确认。现金流储备还需覆盖支付结算延迟、冻结或争议。

### 21.3 获客成本上限

不从未经测量的 churn 推算无限 LTV。用首年贡献作保守预算：在此模型下，试验性付费获客目标可暂设 ≤ $20/位付费用户；若获客成本超过首年贡献且无留存证据，不扩大投放。

SEO/社区不是免费：记录写作、录屏、答疑时间。若服务型收入比订阅更快，必须扣真实交付工时，不能把定制项目收入当可无限复制 SaaS 收入。

## 22. 海外支付：准入、收款和业务类型一起设计

### 22.1 主体前提

本文不假定已经存在香港、美国或其他海外公司，也不根据当前网络位置判断合法注册地。需确认的真实资料是：**经营主体类型、实际居住/注册地、身份证明、收款账户归属、税务身份、产品类别**。

申请使用真实信息，不借用他人身份、伪造地址或购买支付账户。平台支持某币种不等于某银行账户一定可打款，某国家未被排除也不等于用户已获批准。

### 22.2 候选平台

| 平台/路径 | 本次核对的事实 | 对 GeoD 的建议 |
|---|---|---|
| Paddle | 官方原则上服务未被排除地区的软件业务；有个人/sole trader 身份核验；标准费率 5%+$0.50；公开资料列出 CNY payout [P01][P02][P04][P05] | **可选托管软件订阅的优先申请候选**，但域名、主体、产品、银行和结算链路全部过审后才可售 |
| Lemon Squeezy | 支持国家取决于银行或 PayPal payout；当前银行名单未列中国大陆；有国际、订阅、PayPal 与 payout 附加费 [P08–P10] | 备选；不能因为有 PayPal 就承诺大陆账号一定可收款 |
| Stripe Payments | 当前直接商户支持名单未列中国大陆；香港等另有支持；Atlas 是另一条真实主体建立路径 [P11] | 不作为未确认海外主体的即时默认；不能将 Treasury/stablecoin 产品当 Payments 商户替代 |
| 合同 + 合规服务收款 | 本文没有核验用户现有银行/企业收款能力 | 配置、咨询、定制等服务由实际主体与收款机构确认业务类型、票据和税务后启用 |
| 开源赞助 | 各平台有自己的主体与 payout 条件，本次未逐一审核 | 只设入口规划；不能默认走 Paddle 伪装商品 |

### 22.3 Paddle 的关键限制

官方 AUP 面向真实软件业务；以人工服务为主要产品通常不适合，纯咨询等受限；没有真实软件/服务交付的捐赠、赞助等也不应混作软件销售。[P03]

因此必须将 **Cloud 软件订阅、软件相关支持附加项、纯定制服务、赞助** 分开提交说明；软件相关支持是否可随产品出售仍要以平台审核为准。不能写“所有收入都接 Paddle”。

另一个审核重点是数据下载业务本身：Paddle 的 AUP 也限制侵犯第三方条款/版权或使未经授权的数据访问成为可能的产品。申请前必须检查当前功能、README、官网、演示与默认图源，真实展示仅开放数据或有明确授权的工作流，不能只改商品名字、隐藏原有能力来通过审核。[P03]

MoR 处理其作为交易卖方负责的销售税/VAT等环节，不自动替卖家完成自身所得税、经营登记、入账、外汇或所有法域义务。需保留交易与结算凭证，交给熟悉实际主体的会计核对。[P06]

### 22.4 准入与真实打款验证

| Gate | 所需材料/结果 | 未通过时 |
|---|---|---|
| PAY-01 主体确认 | 真实身份/经营类型、受益所有者（如适用）、地址 | 不设置可支付正式商品 |
| PAY-02 商品审核 | 可用软件、真实功能、定价、Terms/Privacy/退款/联系方式、开源说明 | 只开放免费下载与需求联系 |
| PAY-03 银行与币种 | 账户归属、币种、银行接收限制、费用、结算周期 | 不将 CNY 支持视为完成收款 |
| PAY-04 沙箱 | 成功、失败、3DS、退款、取消、重放/乱序回调 | 不上线 Checkout |
| PAY-05 合规真实订单 | 按平台允许的方式完成小额真实交易、收据与权益核对 | 不自刷成交或伪造客户 |
| PAY-06 退款和到账 | 退款正确回收托管权益；达到实际门槛后核对首笔打款 | 保留现金储备，不把应付余额当已到账 |

准入询问信与证据清单已在附件三准备。正式提交前再次核对政策；本文查到的规则并不构成平台对 GeoD 的批准。

## 23. 支付工程、账户与权益

### 23.1 正确链路

```text
Desktop / Website
  → backend creates checkout for approved price ID
  → hosted checkout
  → verified webhook
  → payment/subscription ledger
  → entitlement service
  → authenticated client refresh
```

浏览器 success 页面与 `geod://billing/return` 仅用于回到应用和触发查询。**它们不是付款凭证**。桌面不会处理银行卡，也不会持有商户 secret。

### 23.2 必需数据模型

`Customer / Organization / Membership / Product / Price / Subscription / Transaction / Refund / Entitlement / WebhookEvent / PayoutReconciliation` 独立存储。

付款邮箱不自动等于组织成员邮箱；购买者、账单联系人和使用者可不同。组织需要 owner/admin/member/viewer 等角色，billing 管理单独授权；不能让用户篡改组织 ID 给别人发权益。

### 23.3 回调与账本

按照官方要求验签，使用原始 body，记录事件 ID 做幂等，处理重放、延迟和乱序；Paddle 官方有相应验签说明。[P07] 接收后先可靠落盘再异步处理；失败可重试和人工对账。

状态变化以当前权威交易/订阅状态为准，不能被迟到的“已付款”事件覆盖较新的退款或取消。每日对账核验未处理回调、订单权益不一致和订阅异常；日志脱敏。

### 23.4 权益状态机

| 状态 | 托管服务 | 本地软件 |
|---|---|---|
| Trial | 试用范围与到期时间 | 完整免费能力 |
| Active | 已购买软件服务 | 完整免费能力 |
| Payment pending | 保持此前有效权益；新权益待确认 | 不受影响 |
| Past due | 清楚通知和有期限宽限，不伪装已续费 | 不受影响 |
| Cancel at period end | 到期前继续，展示停止续费日期 | 不受影响 |
| Expired | 按规则只读/导出窗口，停止新的云任务 | 不受影响 |
| Refunded / disputed | 按交易核实调整对应托管权益 | 不删本地文件，不阻断开放功能 |

保留管理员补发/更正工具，但所有人工动作有原因和审计。账户删除、云数据删除、取消订阅不是同一个按钮；用户可以清楚理解各自后果。

### 23.5 平台故障与迁移

BillingAdapter 隔离平台对象与内部产品 ID；不能因为更换支付平台就更换所有用户数据格式。支付故障时停止新购买而非影响本地任务。云付费权益短期可使用有期限缓存；金融最终状态由服务端核实。

## 28. 指标：北极星是可用成果，不是点击数

### 28.1 产品指标

北极星：**每周产生至少一份通过验证成果的活跃用户数**。在未获得遥测同意的安装中无法完整测量，必须报告样本覆盖；不能通过偷偷上传 AOI 补齐统计。

| 指标 | 定义 | 限制 |
|---|---|---|
| Activation | 合格首次使用会话完成一份有效 Artifact | 开始下载不算，样例假任务不算 |
| Time to first useful output | 从选定真实任务到输出通过验证的时间 | 外部网络与数据大小分组 |
| Task success | 成功、部分成功、失败、用户取消分开 | 无覆盖不是同一种失败 |
| Repeat usage | 30天内有第二次实际任务 | 按真实频率，月度项目不强看日活 |
| Recipe reuse | 同配方在新区/新日期真实再运行 | 复制文件不算 |
| Support burden | 每活跃/付费用户工时与工单类型 | 直接影响毛利 |
| Paid conversion | 已付款并完成权益确认的客户/合格试用者 | 不用全部 GitHub 下载作分母 |
| Revenue quality | 退款、争议、续费、收款差异 | annual cash 与 MRR 分开 |

### 28.2 事件与隐私

可选事件：`app_first_run`、`source_connected`、`search_completed`、`job_submitted`、`artifact_validated`、`recipe_reused`、`checkout_started`、`entitlement_activated`。

默认只含应用版本、OS、操作类别、结果码、耗时档位；不含精确范围、客户项目名称、文件路径、邮箱或完整 Provider URL。账户/支付事件只用于必要服务与财务目的，营销分析另有同意与说明。

浏览器 UTM 不自动识别桌面使用者。跨站到桌面归因使用用户同意的短期 referral token 或用户自报来源；不能用设备指纹和精确位置暗中拼接身份。

## 29. 完整范围下的落地顺序与上线门禁

本节是依赖与风险管理，不是把产品重新缩成 MVP。**完整终态由本文及附件二覆盖，具体发布时间必须依据团队能力和真实验收确定。**

### 29.1 并行工作流

**产品/需求流**：访谈、样例任务、完整 IA、页面状态、可用性对比。

**工程流**：共享契约与安全边界 → Provider/Job/Artifact → 数据域与 Viewer → Recipes/CLI/MCP → 可选云与团队。

**商业流**：付费假设与包装 → 真实主体/商品准入 → 支付沙箱与对账 → 合规真实交易/打款 → 小范围真实付费验证。

**增长流**：官网信息结构与样例资料 → 英文教程与演示 → 社区参与 → 发布活动 → 看使用与付费数据调整。

### 29.2 发布前不可绕过的门禁

门禁按实际发布对象适用，详细编号与证据见[附件06第7节](06-Decisions-Contracts-and-Release-Gates.md#7-分开的发布门禁)。免费桌面发布不以商户审核、Checkout或银行到账为前置条件；云服务即使免费试用也需通过云端门禁。

1. **桌面/所有数据能力**：许可与来源可追溯，无已知禁止源的离线入口；固定样例跨工具验证 CRS、边界、dtype、scale/offset、NoData 与完整性。
2. **桌面发行**：按宣称支持的平台完成安装、升级、磁盘不足、断网与任务恢复验收，不误删成果；未测试的平台不宣称通过。
3. **云服务上线**：身份和租户隔离、上传范围、同步冲突、备份恢复、导出删除、成本控制和故障降级已验证。
4. **收费启用**：已选商品、真实主体与收款路径审核、交易回调、退款/取消、权益和对账就绪；未批准商品不售卖。受控实单和实际结算另留记录，未到账前不宣称收款闭环完成。
5. **所有公开推广**：截图、参数、支持格式和性能对应实际版本；目标或原型明确标注，不能变成已实现承诺。
6. **对应发行的运营**：英文文档、支持与故障说明就绪；提供云服务时另有数据导出和停止服务预案。

### 29.3 上线后90天运营计划（不等于90天完成开发）

| 时段 | 动作 | 交付 | 评估 |
|---|---|---|---|
| 发布准备期 | 18人研究、3条对照工作流、支付审核、签名与文档 | 研究记录、真实演示、准入结果 | 哪些问题已有强免费替代 |
| 发布后1–30天 | 6篇高质量任务教程、每周1个演示、选择相关社区发帖 | 示例/教程/FAQ、真实使用反馈 | 首次成果成功率、阻塞原因 |
| 发布后31–60天 | 访谈回访、配方分享、教育者/顾问合作尝试 | 至少3个经许可的真实案例目标 | 重复任务与合格云试用 |
| 发布后61–90天 | 根据支付/续用优化价值，决定是否小额投放 | 价格实验结果、成本表、渠道复盘 | 贡献毛利、支持负担、渠道回收 |

上述数量为执行目标，不是结果保证。未达到付费使用证据前，不同时大规模买广告、办海外公司、招聘销售和承诺企业 SLA。

## 30. 风险登记与调整条件

| 风险 | 早期信号 | 设计/运营措施 |
|---|---|---|
| 免费替代足够 | 用户完成一次后回官方 Browser/QGIS | 追踪跨源与重复交付价值，不再扩无差异按钮 |
| 开源信任受损 | 现有功能被锁、付费表述含混 | 本地免费边界公开；商业变更单独审查 |
| 支付无法准入或结算 | 审核拒绝、银行不支持、余额长期未打款 | 软件/服务/赞助分开；不伪造主体；保持免费下载 |
| 数据版权问题 | 源限制离线却可创建任务 | Provider策略+后端门禁；更新审查记录 |
| 正确性差 | 输出错位、指数数值不合理 | 优先修 grid/CRS/scale/mask，暂停宣传该工作流 |
| 数据源单点 | 服务停用、签名过期、限流 | adapter、多路径、费用透明、降级与日志 |
| 原生依赖重 | 包体/崩溃/跨平台差异 | 按需能力包、隔离 worker、明确支持矩阵 |
| 功能全面但操作沉重 | 首次任务找不到入口 | 渐进呈现、不把全部选项常驻首屏 |
| 云成本失控 | 原始数据通过 GeoD 服务端转发 | 控制面/数据面分离、用户自有存储、预算硬限 |
| 人工支持吞噬收入 | 每客户年工时高于定价假设 | 清楚支持范围、改善产品、专门服务报价 |
| 隐私与采购阻力 | 不允许 AOI/文件出网 | Local-first、可禁云、自托管评估、不假装零网络 |
| 推广与实现不一致 | SEO页面支持未发布格式 | 文案由版本能力清单驱动，样例持续验证 |

建议决策检查点：目标用户反复使用但不需要云服务，就不以订阅为唯一成败标准；若连本地替代优势都无法验证，停止扩更多数据源，回到核心工作流。收款问题不通过规避风控解决，产品问题不通过更大广告预算掩盖。

### 最终验收定义

GeoD Global 的设计完成，不是“画了一个深色首页”，也不是“列了30个功能”。它必须能回答：

**谁需要什么成果 → 为何不用现有替代 → 如何完成并证明正确 → 怎样被目标用户发现 → 哪个额外价值值得付费 → 钱如何合法到账 → 出错、退款或停用后用户怎么办。**

本文与附件将这些问题落实到对象、页面、工作流、权限、商业包装、渠道、支付账本、测试和运营门禁。所有来源及其边界见 `04-Research-Sources.md`。
