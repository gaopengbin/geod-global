# GeoD Global — 完整产品与海外商业化设计包

**版本：1.2 · 初稿日期：2026-09-20 · 独立仓库决策：2026-09-21 · 负责人：高鹏彬**

这是一套针对 GeoD 独立海外产品体验的完整设计，不是将现有 UI 翻译成英文，也不以首版/MVP 缩减目标范围。

**现行仓库边界已由用户确认：GeoD Global 在 `G:\code\geod-global` 独立建仓，与国内版 `G:\code\tif-downloader` 分开维护。** 两者分别拥有依赖、配置、构建和发布流程；未来共享能力通过版本化包或固定版本的库接入，不以跨仓源码路径或借用本机 `node_modules` 连接。完整决定见附件08。

覆盖：**市场需求 → 目标客群 → 竞争与定位 → 完整产品 → 视觉与交互 → 数据与架构 → 许可与隐私 → 商业模式 → 定价假设 → 支付与到账 → 官网与推广 → 留存和支持 → 工程验收**。

## 三个需要保留的修正

**现状与目标分开。** 国内版参考基线声明的二维依赖是 Leaflet / MapLibre，不能把 OpenLayers 当作已落地现状；GDAL 是可选依赖，完整处理能力仍需实际打包和测试。对应 [R03][R04]。这些事实不自动成为 Global 新仓库的依赖清单。

**免费开源与付费服务分开。** 现有 MIT 权利不收回；本文建议免费本地工作流与可选托管软件、组织服务、独立专业服务分离。新商业模块和价格是待确认提案，不意味着已经决定给现有 CLI、批处理或数据源加锁。对应 [R02] 及总纲第19–23节。

桌面 Pro、Cloud/Teams 与专业服务仍是待比较的方案。保护已有发行权益不等于用户已决定未来所有新增本地能力免费，也不等于已决定开发全部云服务；准确决策状态见附件06。

**支付接入与成功收款分开。** 地区/币种列表、商户审核、商品 AUP、买家付款、退款和银行结算是不同事项。Paddle 不是所有咨询或赞助的万能通道。对应 [P01–P11]。

## 使用方式

先审总纲中的定位、业务边界和决策日志，再使用执行清单编排工作。完整设计允许工程按依赖交付，不把工程排序误解为删掉其余目标。

执行时先按附件08限定新仓库边界，再将附件05中的国内源码位置作为只读参考，最后查附件06的契约与依赖。附件05保留历史审计，不授权迁移或修改国内工作树。免费桌面、云服务和收费启用分别验收；商户尚未批准不阻塞免费桌面工程。附件07及原型用于审阅交互，不能替代产品实现或真实成果验收。

将执行清单交给 Codex 时，一次选择一个工作包；要求先检查仓库实际代码，再制定修改计划、测试和验收。文档里的拟议 CLI、目录结构、页面和模型不是已实现接口。

英文模板含 `[占位符]`，发布前替换，并只使用对应版本真正支持的能力。文档中的价格、容量、预算和性能数字都不是已验证市场结果。
