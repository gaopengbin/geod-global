**F02依赖解释**：F02a定义验证协议和提交门槛，先于具体处理器；F02b按格式随对应X工作包交付，不等待X01–02全部完成。F03可以展示待验证记录，只有通过对应F02b并提交的产物才算有效成果。完整依赖、状态归约和具体开发队列见[附件06](06-Decisions-Contracts-and-Release-Gates.md)，其中三维工作包已撤下。

**仓库边界**：所有新工程在独立 Global 仓库实施；“共享”默认指 Global 的桌面/CLI/MCP入口。国内代码仅作参考，未来复用通过明确版本的库，不跨仓引用源码或本机依赖。独立安装/构建与发布隔离要求见[附件08](08-Repository-Boundary.md)。

## 2. 产品与设计交付清单

### WP-R01 — 目标用户与付费假设

**交付**：18位目标用户研究计划、招募记录、访谈问题、去敏任务样例、现有工具链、频率、预算决策者与云限制。

**验收**：记录已完成数量而不是把计划数量当成果；分别统计“有痛点”“反复使用”“明确预算”“真实付费”；保留反例，不只摘用户夸奖。至少三个真实任务可用于替代工具对照测试。

### WP-R02 — 竞争与任务基准

**交付**：Copernicus Browser、QGIS插件/脚本、GeoD候选实现的同条件任务对比。

**验收**：同数据、同区域、同机器/网络条件；记录结果正确性、手动步骤、耗时和恢复表现。未经测量不用性能倍数；免费替代做得好的部分如实记录。

### WP-D01 — 完整信息架构

**当前交付**：Home 的 Agent 对话和完整二维来源目录，Explore、Workspace、My Data、Tasks；Settings与Help在侧栏底部。未接入来源在看板显示待接入，不提供执行入口。Cloud/Teams/Billing暂不提供入口。Area/Scene/Layer/Recipe/Job/Artifact 对象关系仍保留。

**验收**：同一AOI跨数据域不丢；用户不创建账号/项目即可开始本地工作；从任意任务能找到成果与参数；从成果能找到来源与配方。

### WP-D02 — 设计系统

**交付**：Light/Dark/System tokens；字体、字号、间距、色彩、图标、状态、表单、表格、列表、弹窗、通知和快捷键规范。

**验收**：避免全套默认组件皮肤；主操作14px左右、辅助信息不普遍降到11px；键盘焦点与200%缩放可用；颜色不是唯一状态信号。跨平台截图比对。

### WP-D03 — 全页面与状态设计

**交付**：总纲第7节全部页面，至少1440×900、1280宽和高DPI布局；每个异步页面的空、加载、正常、部分、错误、离线状态；权限不足、费用确认、覆盖输出、未知CRS的特殊状态。

**验收**：不是只有一张首页；窄窗口面板有收起规则；结果列表可扫描大量数据；每个错误都有恢复路径，不只“请重试”。

### WP-D04 — 国际化与文案

**交付**：英文UI词表、日期/数字/单位规则、错误码文案、中文开发说明、长文案布局测试。

**验收**：采集日期不被翻译成服务更新时间；公制/英制显示转换不改变数据单位；所有新文本走i18n，用户不需要微信获得支持。

## 6. 关键端到端用户旅程

### E2E-01 — 无账号完成开放数据获取

全新安装 → 不登录GeoD → 选择可用公开数据 → 创建区域 → 检索真实场景 → 看预览与来源 → 下载资产 → 输出验证 → 打开文件夹/下游查看。

**通过**：界面和文件一致；没有强制订阅；无秘密遥测；缺少第三方认证时只要求对应来源认证，而非GeoD付费。

### E2E-02 — 同一区域的多数据交付

区域固定 → 选择影像/高程/矢量 → 分别确认授权和输出 → 提交组合任务 → 生成带独立元数据的交付包。

**通过**：区域、CRS与分辨率选择清楚；不同数据不被硬拼同一种像素；部分来源失败不污染其他成果。

### E2E-03 — 多时相遥感与科学输出

选择时间窗口 → 指定选景/质量策略 → 缺观测窗口保留缺失 → 正确应用掩膜与scale/offset → 输出统一网格的指数序列及清单。

**通过**：RGB预览不冒充NDVI数值；没有伪造日期；固定输入重跑可复现或解释源数据变化。

### E2E-04 — 大文件失败恢复

下载/处理进行中 → 模拟断网/磁盘满/杀进程 → 重启 → 展示可恢复阶段 → 继续 → 校验输出。

**通过**：不丢任务、不覆写无关文件、不把残缺结果报成功；不支持断点的部分明确说明重下。

### E2E-05 — 本地文件脱离云工作

断网 → 打开COG/矢量/tileset → 指定必要CRS → 预览 → 使用本地可用处理器导出。

**通过**：不依赖支付/身份服务器；需要尚未安装能力包时如实说明，不假装离线完整支持。

### E2E-06 — 桌面配方转CLI/Agent

桌面保存配方 → 去敏导出 → `plan/dry-run` → CLI执行 → 同一Job/Artifact → MCP查询状态。

**通过**：审批、预算和许可与UI相同；stdout机器可读；AI不能写出绕过参数；配方中没有密钥。

### E2E-07 — 付费云服务闭环

免费本地用户 → 主动试用云同步 → 知道将上传字段 → Checkout → webhook确认 → 权益刷新 → 查看发票 → 取消/退款。

**通过**：浏览器回跳不能伪造付款；支付、退款、权益一致；取消不删除本地成果。

### E2E-08 — 团队交接与退出

Owner建立组织 → 邀请Editor/Viewer → 共享去敏配方 → Editor运行 → Viewer查看允许信息 → 移除成员 → 导出组织元数据 → 取消服务。

**通过**：没有越权；成员自己取得上游访问授权；退出路径清楚；共享secret不作为默认机制。

## 7. 数据正确性测试矩阵

| ID | 样例 | 预期检查 |
|---|---|---|
| GEO-01 | EPSG:4326与3857之间的区域 | 经纬度/米不能混用；显示与导出一致 |
| GEO-02 | UTM/本地投影SHP+PRJ | 自动识别配套文件并正确转换 |
| GEO-03 | 缺失或错误PRJ | 请求用户确认/指定，不凭范围瞎猜投影 |

## 9. 跨平台与发行验收

Windows x64、macOS arm64/x64、Linux支持包分别检查：安装、打开、字体/缩放、文件对话框、系统凭据库、网络代理、路径空格/非ASCII、长路径、取消、恢复、更新、卸载。

特别检查：

- WebGL不可用时有降级/诊断，不白屏。
- 原生库缺失时只影响对应能力，不能整应用退出。
- 任务写出过程中更新或退出有明确保护。
- 更新签名与OS签名均验证，签名密钥不入仓库/日志。
- CN/Global并存时数据库、URL scheme、缓存和更新渠道不串用。
- 输出目录属于用户；卸载页面明确默认保留。
- 发布包对应commit、构建依赖、SBOM和SHA-256，不仅提供一个未知二进制。

## 10. 研究与商业的验证标准

以下是研究门槛提案，不是必须凑出来的KPI：

**需求证据**：至少3个带真实输入/输出约束的完整工作流；所有假设允许被反例推翻。

**可用性证据**：目标用户不用作者现场替其操作，能完成核心任务；记录中途求助与失败。

**差异证据**：与免费替代进行同任务对照；找到真实优势，而不是只比较截图。

**付费证据**：区分“愿意试”“愿意报价”“签试点合同”“实际收款”；没有收款不写成已验证商业模式。

**增长证据**：记录渠道来源、合格用户、有效成果与再使用；不以曝光或stars一项决定投放。

**收款证据**：主体/商品审批、交易/退款/权益正确、真实结算到账。任何一个缺失都只叫“支付接入进行中”。
